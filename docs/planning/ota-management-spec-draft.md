# 在线设备 OTA 推送与后台选择

规格 #95，关联 #88。2026-11-13 用户调整优先级：先保证全部在线设备 OTA 推送、后台显示与选择，其他能力进入 backlog，不阻塞本次主线。本文件替代先前完整批量维护范围；原需求保留于 ota-management-backlog.md。

## Problem Statement

已验证的 #18 能通过当前产品语音会话向指定设备推送 OTA，但需要运维命令。管理员需要在后台看到可推送的在线设备、选择 GitHub Release 固件，并对单台、多台或全部当前在线兼容设备发布。

## Solution

复用现有在线会话与设备升级工具。后台提供已校验固件目录、设备在线/可推送状态、选择与预览、确认推送及逐台结果。全部由服务器枚举当前在线设备，覆盖全部分页，确认时固定目标集合；发送前重新校验会话、许可、工具及兼容性。离线、不兼容、缺少必要硬件信息、无唯一有效会话或工具未就绪的设备显示原因，不排队等待未来上线。

## Current Scope

- 小智后台上传 `.bin` 与 `manifest.json` 选包，导入固定字节并核验 SHA256、真实版本/ELF、板型与布局；GitHub Release 导入作为兼容入口保留；预发布明确标识，不自动追随 latest。
- 真实后台显示产品设备及在线/可推送状态，支持单台、多选、全部在线兼容设备，预览目标与排除原因后明确确认。
- 复用当前固件的 self.upgrade_firmware 主动推送，不要求设备先更新到新的维护协议。在线定义以服务器唯一有效产品会话为准，不能用历史 last_seen 代替；发送前再次校验。
- 逐台有界执行，固定目标与固件、持久化操作号和传输结果。回执丢失保留结果待核对，服务重启或重复点击不能自动重发。此次掉线设备标为未发送，不保留离线补发任务。
- 已下发/设备已接受不等于安装成功。后台准确区分未发送、已接受待安装核验、失败和结果未知；只有足够真实运行产物证据才能标记安装确认。没有配套固件回报时保持待核对，不伪造进度。
- 维护不得改变设备身份、归属或许可；不能为已撤销准入或无有效会话设备绕过权限。用户已将停用/未绑定独立维护移出本轮。
- 当前升级工具可能中断正在进行的语音，发布确认界面明确提示本次会立即升级并重启；不承诺自动等待空闲。
- 同一实际固件不作强制重装；版本字符串相同但产物不同必须区分。保留应用镜像/硬件兼容校验，未知信息不猜测。

## Testing Decisions

沿用用户已批准的真实管理页面/HTTP、设备升级协议、Ubuntu与P4验收入口，缩减到在线推送范围。测试管理员权限、选包校验、跨页全部在线目标、会话变化、未选设备隔离、有界多台下发、未知结果不重发与重启后记录。Ubuntu协议模拟不能代替P4真实下载、自动重启、目标产物及身份保持证据。实机只对明确指定目标验收，不因开发全部按钮而自动推送全部现存设备。

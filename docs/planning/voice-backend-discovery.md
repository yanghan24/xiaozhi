### 硬件资料同步更正（2026-11-06）

依据[筑音设备接入资料核查稿](../../筑音设备接入资料_核查稿_2026-11-06.md)，此前将本批设备写为 ESP32-S3 属于需求记录错误。当前硬件依据为用户提供的微雪 ESP32-P4-Touch-LCD-4.3、ESP32-P4 主控、32MB Flash 和 32MB PSRAM；正式整机型号仍待定，不能用开发板型号替代。

- 官网对应候选完整型号为 ESP32-P4-WIFI6-Touch-LCD-4.3，带 ESP32-C6-MINI-1 无线协处理器及 4.3 英寸 480×800 电容触摸屏；完整型号对应关系、实物丝印、硬件版本与芯片 revision 仍需核对。
- 厂商提供的小智 v2.5.2 适配是参考资料，不能认定为样机当前固件。当前固件版本、源码、配网入口及自建服务器配置方式须以交付工程和实机为准。
- 屏幕具备二维码显示的硬件条件，不表示当前固件已实现动态二维码、账号菜单或设备端首次绑定确认；这些能力需核实或开发。
- OTA 镜像、实际分区、应用槽容量、凭据保存与恢复、升级结果上报和回滚均需固件及实机证据；不能由 Flash 容量或候选上游配置推定已支持。实机验证按仓库约定在 Ubuntu 服务器环境进行。

正式开发规格为 [#10](https://github.com/yanghan24/xiaozhi/issues/10)，子任务 #11–#19 保留原生依赖。#4 设备协议与 #5 Ubuntu 服务重启/持久化已验收；真实设备验收继续由 #6 跟踪。Ubuntu 已连接并部署，见[验收记录](../verification/2026-11-06-ubuntu-deployment.md)。用户决定等公网映射就绪后再做 #11 的真实 OIDC 联调，暂不进行规范通真实调用；#12 当前采用 Edge TTS 测试，不能替代正式集市合成验收。

### 当前集市接入基线（2026-11-06）

- 继续采用已确认的第一种方案：手机扫描音箱二维码 → 小智设备绑定页 → 集市 web OIDC → 小智回调并确认绑定。客户端为 `web`，使用授权码、PKCE S256 和 `client_secret_basic`；Secret、Token 与 Key 仅由后端保管。新版第 8 节的 `device` 流程不纳入当前实现。
- [新版接入文档 (1)](<../../元筑AI集市应用接入接口文档(1).md>)作为当前通用契约，[旧版](../../元筑AI集市应用接入接口文档.md)仅供对照。两版同标 v1.0/2026-11-05，须用文件名与[内容哈希](../development/ai-market-contract-review-2026-11-06.md)区分。
- OIDC issuer 为 `https://aimarket.hncig.cn/oidc`，使用不带端口的正式端点；规范通资源示例保留用户提供的 `:4090`，不混用身份端点与资源地址。
- 实际 web Client ID/Secret、获准 scope 和登记的 HTTPS 登录/退出回调、注销通知仍待核对已有私有配置。文档中的示例不是已注册配置；用户已有独立账号，不重复索取整套服务器或接口资料。
- 新版允许 `offline_access`、刷新轮换和应用授权撤销。Key 可无固定到期时间且按用户/应用共享；单台退出只停止目标设备的本地调用及输出，单台退出和解绑均不撤销共享授权；真实集市授权失效另按实际范围处理。具体失败、并发和验收约束见[契约核对](../development/ai-market-contract-review-2026-11-06.md)。

### 已确认的设备绑定交互（2026-11-06）

依据 [#13](https://github.com/yanghan24/xiaozhi/issues/13) 的 Q1–Q8 讨论，以下为需求决定，尚未实现或通过固件验收。

- Q1：未绑定设备联网后自动显示绑定二维码；已绑定且授权有效时直接使用。退出或需重新授权时显示登录二维码，临时断网不视为退出，保留归属。
- Q2：绑定/重新登录请求有效期 10 分钟，过期自动换码。旧链接提示重扫，最终确认时再次校验有效期；有效集市登录可以复用，过期设备请求不能复用。
- Q3（2026-11-09 更新）：首次绑定仅手机登录并明确确认，不要求音箱端再次确认；登录成功本身不自动绑定。
- Q4/Q5：每台设备使用独立小智接入凭据，集市凭据留在后端。音箱设置需提供“账号与绑定”限时二维码入口；敏感操作验证原归属账号，持有码不等于获授权。
- Q6：只接纳预登记设备，自报 Device-Id 或修改服务器地址不构成可信认证。暂定硬件提供稳定标识及板型、小智管理员批量登记并生成凭据、硬件逐台写入并核对；工具/写入分工、标识及配置存储方式待源码确认，凭据不放普通清单或 Git。
- Q7：扫码不锁定设备，允许多个手机进入；首个完成所有有效确认的请求原子取得唯一归属，其他请求提示已绑定。首次绑定不增加音箱端确认。
- Q8：凭据丢失或损坏由管理员核验设备后补发、撤销旧凭据，交付/维修环节写入；保留设备记录及原归属，不向客户开放秘密查看或下载。普通恢复出厂应保留设备身份，实际行为待固件验证。

已有交接记录确认设备可修改 OTA 地址、固件仍在修改；该事实不代替上述新增功能及 OTA 升级能力验收。

### 2026-11-05 接入问答确认

> 历史访谈：会话到期、单台退出和运营正文权限以 2026-11-09 收口为准。

本轮用户答复更新下列产品行为。未给出具体参数、接口样例或实测结果的事项仍列为待验证，不将产品要求视为集市已经实现的协议能力。

- 长期使用：绑定后在登录状态及业务授权持续有效期间使用，无需反复登录，再次登录的间隔应较长；具体时长尚未给出。关闭手机页面不等于主动退出登录。未登录、退出登录或授权失效时停止使用对应 Key，保留设备归属，通过原账号扫码登录并取得有效授权后恢复使用。
- 绑定条件：账号没有规范通权限或余额不足仍可绑定，当前不在绑定阶段增加权限或余额提示。这不代表集市资源调用一定会成功。
- 退出、解绑与重置：手机退出登录后，小智侧立即停止使用对应 Key 调用规范通和集市语音模型，设备仍归原账号；原账号重新登录并取得有效授权后恢复使用。换绑须由原归属账号在扫码后的设备页面重新认证并确认解绑，符合 ADR-0005。恢复出厂设置同样保留后台设备归属。退出后禁用 Key 是已确认的产品规则，具体注销通知与凭证失效机制需按集市契约接入并验证。
- 运营访问：运营人员沿用小智后台的管理员账号登录，客户集市身份与运营权限分别校验。运营管理员默认仅查看设备状态、用量和错误信息；查看完整对话内容需额外授权并记录访问，具体授权角色待确定。用量展示使用可获得的调用统计，不扩展为本地结算账本。
- 对话上下文：首版仅在一次连续对话中保留上下文，不跨设备共享，也不在下一次新对话中自动续接旧话题；保存 30 天的文字记录与可续接的会话上下文分别管理。
- 语音播报：播报正文，略过网址和引用编号，支持用户打断；具体引用样例和取消协议在接口联调中核实。
- 登录方式：用户确认集市通过浏览器微信扫码登录。手机扫描音箱后，如何在同一部手机上完成集市认证仍需实际验证；不能据此推定手机已能完成第二次扫码。
- 失效处理：账号停用、权限或授权撤销按用户要求立即生效，小智侧的错误分类与返回由开发方设计；集市实际状态、失效通知方式及在途请求行为需联调核实。
- 联调安排（早期记录，当前执行以上方基线为准）：用户曾表示可开始联调；随后明确等待公网映射并暂不测试规范通。仍需核对实际客户端配置和固件资料。“暂时没有限制”用于安排实际容量测试，不作为无限并发能力的保证。

本轮资料包括用户提供的《元筑AI集市应用接入接口文档》v1.0（2026-11-05），以及[规范通控制台的 API/MCP 页面](https://aimarket.hncig.cn:4090/console/agent/156fd2a5-ade8-4800-b206-21a024d23760?tab=api)。链接中的标识用于定位控制台智能体，实际调用地址、参数和资源标识以页面接口说明为准，不从控制台 URL 推断。

只读检查已从该页面公开前端确认通用说明：原生 API 使用集市 Bearer Key，先创建会话再发起对话；MCP 使用 Streamable HTTP，后续通过 `conversation_id` 续接。页面的具体文档数据由 `GET /consoleapi/agents/156fd2a5-ade8-4800-b206-21a024d23760/native-docs` 加载，无登录态访问返回 HTTP 401；该 GET 地址仅用于控制台加载文档。用户随后补充了会话创建、流式对话请求、响应示例和 MCP 地址，已记录于[接口资料](../development/ai-market-api.md)：原生 API 的 app_id 与集市智能体 ID 不同，创建响应的顶层包含 request_id 与 conversation_id；后续向 `/api/ai_apaas/v1/app/conversation/runs` 提交 app_id、conversation_id、query 和 stream 即为页面的流式提问示例。响应样例包含 answer、is_completion 和 content，但正文是增量还是累计、结束/错误事件及取消规则仍待核实；end_user_id 仅作上游业务标记，计费以 Key 所属账号为准。集市语音代理契约仍待取得，尚未执行真实调用。

早期暂定千问作为集市语音合成候选；当前测试已改用 Edge TTS。以下保留千问资料依据。已直接查阅[千问官方实时语音合成指南](https://help.aliyun.com/zh/model-studio/qwen-tts-realtime)及协议文档，当前官方示例使用 `qwen-audio-3.1-tts-flash`，具备分段文本输入、流式音频输出和取消能力；作为优先联调候选，详见[千问调研](../development/qwen-tts-research.md)。集市是否开放该型号、是否透传 WebSocket 和取消仍待确认；调用继续使用归属账号的集市 Key，经集市处理权限和结算。

2026-11-06 收到的[新版接入文档 (1)](<../../元筑AI集市应用接入接口文档(1).md>)替换了原版的生命周期规则：获准 `offline_access` 并取得用户同意后可使用轮换刷新令牌，连续 30 天未刷新才失效；Access/ID Token 仍为 5 分钟。Key 的 `expires_at: null` 表示无固定到期时间，网页或刷新令牌自然到期不自动撤销它。小智仍按已确认要求检查本地登录/调用许可及业务授权，退出后停止使用 Key；应通过新增应用授权撤销接口终止集市调用能力。该撤销影响同用户同应用的共享凭据，并不取消已受理请求。新版设备授权不用于当前方案，用户已再次确认 web 登录及后端保管凭据。具体修改建议、待确定的退出范围及验收补充见[新版契约核对](../development/ai-market-contract-review-2026-11-06.md)。

### 小智侧调用错误约定

用户将小智侧返回方式交由开发方决定，采用以下分类。它们是小智侧处理结果，不是对集市实际错误码的声明；适配时依据集市正式响应映射，不能仅凭一个笼统的 HTTP 403 推定具体原因。

| 小智侧分类 | 面向客户的提示 | 处理 |
| --- | --- | --- |
| `MARKET_AUTH_REQUIRED` | 授权已失效，请扫码重新授权 | 保留设备归属，展示原账号重新授权入口，不反复重试失效凭证 |
| `MARKET_ACCESS_DENIED` | 当前账号暂时无法使用此服务 | 停止本次调用；按集市明确返回的原因处理，不自动换用其他账号凭据 |
| `MARKET_RATE_LIMITED` | 服务繁忙，请稍后再试 | 遵循上游重试时限，避免密集重试 |
| `MARKET_TIMEOUT` | 本次响应超时，请稍后再试 | 结束本次等待；已收到部分响应或上游执行状态不明时，不自动重发完整生成请求 |
| `MARKET_UNAVAILABLE` | 服务暂时不可用，请稍后再试 | 结束本次调用，记录脱敏的排障信息 |

这些提示发生在实际对话调用失败时；绑定阶段仍遵循不增加权限或余额提示的决定。提示可使用屏幕文字或预置音频，避免依赖刚刚失效的集市语音调用。用户在小智侧主动退出时立即禁止继续使用对应 Key；收到集市注销、登录失效或授权撤销信号时同样立即禁用。在途生成的取消能力和集市失效通知方式需联调确认。

团队分支、检查点和恢复步骤见 [CONTRIBUTING.md](../../CONTRIBUTING.md)。Git 回退用于源码历史；服务部署、数据及已安装的 OTA 固件分别按对应的恢复流程处理。

- [ADR-0003](../adr/0003-oidc-web-login-for-device-binding.md)：采用集市 OIDC 和设备屏幕二维码引导的绑定网页，替换早期小程序入口；首版小智管理后台仅供运营管理员使用。
- [ADR-0004](../adr/0004-extend-upstream-xiaozhi-server.md)：基于上游小智服务端工程二次开发，复用现有管理、语音及 OTA 基础能力。
- [ADR-0005](../adr/0005-backend-owns-device-management.md)：小智管理后台负责设备管理及绑定归属，集市负责身份、应用权限和额度计费。

## 用户流程草案

> 历史草案，当前生命周期边界见 2026-11-09 产品规则收口。

以下顺序用于对齐联调目标，页面和协议细节尚需验证。

1. 用户按设备现有方式打开 Wi-Fi 配网，让音箱联网。
2. 音箱屏幕显示该设备的二维码，用户用手机扫描。
3. 小智侧绑定页引导用户通过集市 OIDC 完成登录或已有账号关联，再回到绑定流程确认绑定本台音箱。
4. 小智管理后台校验登录结果与绑定请求，记录设备与集市账号的关联，向设备提供绑定状态和运行配置。
5. 音箱通过小智语音服务调用归属账号有权使用的规范通及集市语音合成模型，集市负责额度与结算，小智侧处理文本、音频和调用错误。
6. 客户完成绑定后，在登录及业务授权有效期间通过音箱使用规范通；文字记录最长保留 30 天。手机退出登录后保留设备归属并停止使用对应 Key，原账号重新登录且授权有效后恢复使用。客户在扫码后的设备页面，由原归属账号重新确认身份并解绑后转交，小智侧更新设备归属。

## 首版客户与运营入口

- 客户入口集中在设备屏幕二维码引导的小智侧绑定网页，以及音箱本身的使用流程；身份认证通过集市完成，设备绑定由小智侧处理。
- 小智管理后台供运营管理员管理设备档案、绑定关系、运行状态、固件发布及 OTA 结果；客户身份不能访问运营管理页面或运营管理 API。客户专用的绑定接口单独校验身份及操作权限。
- 客户后台设备列表、文字记录查看/删除和 OTA 结果查询界面不在首版范围，不默认新增另一套客户门户。
- 文字记录按账号和设备隔离、保留 30 天并到期清理；首版包括超级管理员在内均不开放完整对话查看或导出，不提供内容代办入口。
- 客户绑定用的 OIDC 身份与运营后台访问权限分别校验；运营人员沿用原小智后台管理员账号登录。

## 后台 OTA 的已确认范围

- 操作权限：由运营管理员上传固件、发起发布并查询升级结果。首版客户不使用管理后台，也不具有固件上传、发布或管理查询权限。
- 升级触发：后台上传固件并确定发布范围后，设备在下次启动或自行检查更新时取得目标版本。首版采用设备主动检查的路径，不要求后台命令设备立即升级。
- 发布范围：支持单台和一批设备，先选择少量设备试点，再逐批扩大。上传同板型新固件不能直接让发布范围外的设备获得该版本。
- 查询与重试：运营后台展示设备当前运行版本、发布目标版本及升级结果，由管理员执行失败重试。结果需要设备反馈或再次上报实际运行版本作为依据，下载响应成功不等同于升级完成。
- 离线设备：等待其重新上线或检查更新；尚未获得结果的设备应保留待确认状态，不直接视为升级失败。
- 固件匹配：发布必须匹配实际板型、芯片 revision 及所需固件产物。ESP32-P4 是芯片平台，不能据此认定不同设备板型共用一个固件包；参考包须核对 P4/P4X 构建与实际芯片版本。

自动回滚、降级发布和掉电恢复能力尚未确认，需结合实际设备固件、分区配置和真机验证，不因采用后台 OTA 就视为已有能力。OTA 作为首版新增功能纳入 2026-12-07 的交付目标，具体联调进度取决于固件和样机资料。

扫码入口、OIDC 回调与屏幕上那台设备的绑定请求必须能够对应；不能仅凭登录成功推定设备已经绑定。微信内网页的真实登录体验需要与集市联调，避免将需要再次展示登录二维码的网页流程直接当作可用的手机操作流程。

## 职责与对接

- 小智管理后台：维护设备档案、绑定归属及运行状态，为运营管理员提供管理界面、管理 API、固件上传、按设备发布及结果查询；负责小智侧绑定流程与接口，将集市身份关联到本地设备记录，客户 OIDC 的绑定流程与运营后台权限分开。
- 小智语音服务：承担设备连接和实时语音处理，根据小智管理后台的设备归属记录，按集市正式授权契约调用规范通及集市语音合成模型，处理对话、音频与调用错误。
- 集市后台：作为账号、微信身份关联、应用权限和用户额度计费的管理方，提供 OIDC、业务授权、规范通及语音模型调用，并负责额度和结算。

已取得集市 OIDC 及凭证领取的接入文档，用户确认通过浏览器微信扫码登录。当前尚未完成真实客户登录、规范通调用或集市语音模型调用验证；Edge TTS 的 Ubuntu 合成检查已通过，真机播放仍待验证。

### 联调所需资料

1. 集市提供：项目实际 web Client ID、后端 Secret、含 `offline_access` 的获准 scope 和登记回调/注销通知；核实首次用户同意、手机登录、刷新轮换、共享 Key 和授权撤销的真实行为。新版已给出生命周期规则，尚需配置及实测。凭据通过约定渠道交付，不写入需求记录。
2. 小智侧设计：设备绑定、解绑、归属查询及转交接口，屏幕二维码对应的绑定会话，以及绑定成功怎样通知或被设备查询；按已确认方式分离客户身份和运营权限。
3. 规范通原生 API 和 MCP 地址、请求字段及响应片段已取得；仍需原始 SSE、会话/取消/错误语义。如选择 MCP，还需工具定义；当前暂不进行真实规范通调用。
4. 集市提供：语音合成模型标识、调用地址、鉴权、音频格式、流式及取消能力。小智侧无需实现独立用量上报、价格计算、余额预占或结算接口。
5. 已有 ESP32-P4-Touch-LCD-4.3 硬件资料；继续核对完整板型、实物 revision、当前固件版本或源码位置、二维码显示与 Wi-Fi 配网方式、是否允许固件改造、样机可用时间，以及 OTA 地址配置、固件产物、分区和升级结果上报方式。
6. 部署环境和测试资源，以及规范通、语音识别和合成服务的并发/配额能力；需要验证 100 台在线及 100 路同时语音对话。

### OIDC 的已核实边界

- 集市提供身份服务，小智的客户绑定流程校验登录结果，以 `iss + sub` 映射用户，再与集市正式提供的账号标识关联；该身份不会自动授予运营后台权限。[OIDC 主体标识规则](https://openid.net/specs/openid-connect-core-1_0.html#ClaimStability)
- OIDC 不规定扫码界面，服务号扫码与微信身份关联可由集市在认证时处理。设备屏幕二维码不意味着采用 OAuth 设备授权流程，具体流程以双方契约为准。[OIDC 授权码流程](https://openid.net/specs/openid-connect-core-1_0.html#CodeFlowSteps)
- 用户登录、设备绑定、规范通访问权限以及设备本身的连接凭证是不同的业务或协议环节，需要逐项联调。[OIDC Discovery](https://openid.net/specs/openid-connect-discovery-1_0.html#ProviderMetadata)

## 验收与阶梯压测草案

用户已接受设备归属、记录保留和最大并发目标。以下为落实这些要求的验证安排，尚未执行测试。

1. 少量与硬件资料一致的 ESP32-P4 真机连接 Ubuntu 服务器，先验证 Wi-Fi 配网、屏幕扫码、手机 OIDC 登录、小智管理后台记录绑定并向设备生效、规范通问答及语音播放的完整链路；记录实际板型、芯片 revision 和固件版本。
2. 用不同账号和设备验证一账号多设备、单设备唯一归属、原账号授权解绑后转交以及按归属账号检查规范通权限；手机退出登录和设备恢复出厂设置均保留后台归属。验证退出后停止使用对应 Key 调用规范通及语音模型，原账号重新登录并取得有效授权后恢复使用；仅关闭页面且登录与授权仍有效时可继续使用。新归属账号不能通过设备转交取得原账号的历史文字记录。
3. 验证客户可通过专用入口完成扫码绑定，但不能访问运营管理页面及运营管理 API；文字记录按账号和设备隔离、30 天到期清理，原始录音不作为历史记录持久保存。客户自助查看和删除页面不在首版验收范围。
4. 验证规范通与集市语音模型均按归属账号的正式授权调用，小智侧正确处理成功、无权限、授权失效及服务异常；额度与结算由集市处理，语音识别费用仍由平台承担。
5. 容量测试按少量真机联调、10、25、50、100 路并发逐级推进，并分别检查连接保持及同时语音对话。规模测试可在真机校准后使用兼容设备协议的模拟客户端，记录模拟与真机各自的覆盖范围。
6. 100 路语音测试必须覆盖设备接入、语音识别、规范通调用、语音合成和音频返回，不能用仅维持 100 个空闲连接替代。规范通和语音服务的限流与配额纳入同一验证链路。
7. 每阶段记录完成率、错误和断线、音频返回情况、首段语音等待时间、资源使用与计量一致性；用户未指定响应时间门槛，实际延迟作为观测结果报告。
8. OTA 先以一台真机验证固件上传、指定发布、设备下次检查更新、重启及目标版本回报，再验证一小批设备和发布范围隔离；升级后复验配网、设备归属及规范通对话。
9. OTA 验证只有获授权管理员能上传、发布、查询管理结果及重试；同时覆盖板型不匹配、离线设备、下载中断和升级结果未回报。已有发布的固件与目标版本应可追溯，新上传的同板型固件不能覆盖正在验证的发布目标。

阶梯节点是工程验证草案；100 路的测试时长、每路轮次与通过标准现已按[产品规则收口](product-rules-2026-11-09.md)确定；100 台同时语音对话是已确认的最终目标，不因中间阶段通过而降低。管理端基线已导入并完成验证，见[源码基线记录](../development/upstream-baseline.md)；集市接入、生产部署及最终容量验收尚未完成。

- 设备会在 OTA 请求中上报运行版本，后台已有更新设备版本的逻辑，可用作升级结果确认的基础。所查代码中未发现完整的发布任务、批次、失败重试和回滚状态管理。[设备版本更新](https://github.com/xinnan-tech/xiaozhi-esp32-server/blob/c8e60d1325650c8a31d00e36d8528f8bb74aeb11/main/manager-api/src/main/java/xiaozhi/modules/device/service/impl/DeviceServiceImpl.java#L82)
- 原文档指向独立的设备固件工程，并要求 OTA 使用适当的应用固件产物（例如 `xiaozhi.bin`），而非整片刷写镜像。后台工程与实际设备固件都需要核对兼容性。[OTA 指南](https://github.com/xinnan-tech/xiaozhi-esp32-server/blob/c8e60d1325650c8a31d00e36d8528f8bb74aeb11/docs/ota-upgrade-guide.md#L49)

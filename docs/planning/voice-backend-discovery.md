# 小智智能音箱后台：需求访谈

## 当前目标与已确认范围

| 项目 | 当前决定 |
| --- | --- |
| 后台 | 基于 xinnan-tech/xiaozhi-esp32-server 原工程二次开发，保留供运营管理员使用的小智管理后台、管理 API 和语音服务 |
| 集市 | 对接 [元筑AI集市](https://aimarket.hncig.cn:4090/)，由集市管理账号、设备归属、应用权限和额度 |
| 客户入口 | 使用集市 OIDC；客户扫描设备屏幕二维码进入身份确认和设备绑定网页，首版不登录小智管理后台，不开发微信小程序 |
| 硬件与网络 | 使用 ESP32-S3 小智智能音箱，具有屏幕，使用 Wi-Fi 配网；具体板型、固件及操作步骤待资料和真机核实 |
| 后台 OTA | 管理员上传固件并选择单台或一批设备发布；设备下次启动或检查更新时升级；支持少量试点后分批发布，由管理员查询结果和重试 |
| 客户与规模 | 外部客户，首批暂定约 350 台设备 |

| 首批应用 | 规范通，复用该集市应用的用户权限 |
| 应用计费 | 沿用 AI 集市的额度和计费规则 |
| 语音识别费用 | 平台承担 |
| 语音合成费用 | 计入用户额度；计量、扣费和失败处理需与集市接口明确 |
| 对话记录 | 按账号和设备区分文字记录，保留 30 天并到期清理；原始录音默认不保存；首版小智后台不提供客户自助查看和删除入口 |
| 容量目标 | 100 台设备同时在线且同时进行语音对话，允许阶梯压测；这是待验证的容量目标 |
| 响应时间 | 用户当前未指定响应时限；实际延迟应在联调中测量 |
| 交付 | 12 月 7 日，按当前会话年份记录为 2026-12-07；先完成少量真机调试 |
| 团队开发与回退 | 采用任务分支、PR 审阅与可定位的功能提交；共享历史通过 revert 恢复；发布关联版本标签、构建产物及数据和固件恢复条件 |

团队分支、检查点和恢复步骤见 [CONTRIBUTING.md](../../CONTRIBUTING.md)。Git 回退用于源码历史；服务部署、数据及已安装的 OTA 固件分别按对应的恢复流程处理。

## 用户流程草案

以下顺序用于对齐联调目标，页面和协议细节尚需验证。

1. 用户按设备现有方式打开 Wi-Fi 配网，让音箱联网。
2. 音箱屏幕显示该设备的二维码，用户用手机扫描。
3. 手机网页引导用户通过集市完成登录或已有账号关联，并确认绑定本台音箱。
4. 集市记录设备归属，小智后台取得生效的绑定关系和运行配置。
5. 音箱通过小智语音服务调用用户有权使用的规范通，返回语音回答；用量按已确认的费用分工处理。
6. 客户完成绑定后通过音箱使用规范通；文字记录最长保留 30 天。设备转交仍须原账号先解绑，具体客户解绑入口与集市接口对接确认。

## 首版客户与运营入口

- 客户入口集中在设备屏幕二维码引导的身份确认、集市账号关联和设备绑定网页，以及音箱本身的使用流程。
- 小智管理后台供运营管理员管理设备运行、固件发布及 OTA 结果；客户身份不能访问管理后台页面或管理 API。
- 先前约定的客户后台设备列表、文字记录查看/删除和 OTA 结果查询界面从首版范围移出。是否在集市或其他客户入口提供这些自助功能，后续再定，不默认新增另一套客户门户。
- 文字记录按账号和设备隔离、保留 30 天并到期清理；客户不登录后台不意味着运营管理员可以任意查看或删除客户内容，具体内容访问和代办权限仍待明确。
- 客户绑定用的 OIDC 身份与运营后台访问权限分别校验，运营人员的登录及授权方式需在管理端适配时明确。

## 后台 OTA 的已确认范围

- 操作权限：由运营管理员上传固件、发起发布并查询升级结果。首版客户不使用管理后台，也不具有固件上传、发布或管理查询权限。
- 升级触发：后台上传固件并确定发布范围后，设备在下次启动或自行检查更新时取得目标版本。首版采用设备主动检查的路径，不要求后台命令设备立即升级。
- 发布范围：支持单台和一批设备，先选择少量设备试点，再逐批扩大。上传同板型新固件不能直接让发布范围外的设备获得该版本。
- 查询与重试：运营后台展示设备当前运行版本、发布目标版本及升级结果，由管理员执行失败重试。结果需要设备反馈或再次上报实际运行版本作为依据，下载响应成功不等同于升级完成。
- 离线设备：等待其重新上线或检查更新；尚未获得结果的设备应保留待确认状态，不直接视为升级失败。
- 固件匹配：发布必须匹配实际板型及所需固件产物。ESP32-S3 是芯片平台，不能据此认定不同设备板型共用一个固件包。

自动回滚、降级发布和掉电恢复能力尚未确认，需结合实际设备固件、分区配置和真机验证，不因采用后台 OTA 就视为已有能力。OTA 作为首版新增功能纳入 2026-12-07 的交付目标，具体联调进度取决于固件和样机资料。

扫码入口、OIDC 回调与屏幕上那台设备的绑定请求必须能够对应；不能仅凭登录成功推定设备已经绑定。微信内网页的真实登录体验需要与集市联调，避免将需要再次展示登录二维码的网页流程直接当作可用的手机操作流程。

## 职责与对接

- 小智管理后台：为运营管理员保留管理界面和管理 API，适配集市设备归属及规范通权限，提供固件上传、按设备发布及结果查询；客户 OIDC 的绑定流程与运营后台权限分开，本地运行数据如何与集市映射或同步需在接口设计中确定。
- 小智语音服务：承担设备连接、实时语音处理及规范通调用，提供语音识别与合成的用量数据。
- 集市后台：作为账号、设备归属、应用权限和用户额度的管理方，提供正式的授权、绑定、应用调用及必要的计量结算接口。

集市开发已经提出提供 OIDC；用户确认现有微信扫码登录使用服务号接口。具体接入契约仍未取得，当前没有做真实登录或应用调用验证。

### 联调所需资料

1. 客户绑定用 OIDC 的发行者与 Discovery 地址、客户端注册和回调约定、手机扫码后的完整时序、稳定用户标识；另需明确运营后台的登录及角色授权方式。
2. 设备绑定、解绑及归属查询接口；如何生成或查询屏幕二维码对应的绑定会话，以及绑定成功怎样通知或被设备查询。
3. 规范通的应用标识、访问权限检查、调用鉴权、流式响应、会话及错误语义。
4. 语音合成用量如何计价并计入集市额度，余额不足、失败和重试的结算规则；不得将 OIDC 登录令牌自动视为可用于所有业务 API 的授权。
5. ESP32-S3 音箱的具体板型、固件版本或源码位置、二维码显示与 Wi-Fi 配网方式、是否允许固件改造、样机可用时间，以及 OTA 地址配置、固件产物、分区和升级结果上报方式。
6. 部署环境和测试资源，以及规范通、语音识别和合成服务的并发/配额能力；需要验证 100 台在线及 100 路同时语音对话。

### OIDC 的已核实边界

- 集市提供身份服务，小智的客户绑定流程校验登录结果，以 `iss + sub` 映射用户，再与集市正式提供的账号标识关联；该身份不会自动授予运营后台权限。[OIDC 主体标识规则](https://openid.net/specs/openid-connect-core-1_0.html#ClaimStability)
- OIDC 不规定扫码界面，服务号扫码与微信身份关联可由集市在认证时处理。设备屏幕二维码不意味着采用 OAuth 设备授权流程，具体流程以双方契约为准。[OIDC 授权码流程](https://openid.net/specs/openid-connect-core-1_0.html#CodeFlowSteps)
- 用户登录、设备绑定、规范通访问权限以及设备本身的连接凭证是不同的业务或协议环节，需要逐项联调。[OIDC Discovery](https://openid.net/specs/openid-connect-discovery-1_0.html#ProviderMetadata)

## 验收与阶梯压测草案

用户已接受设备归属、记录保留和最大并发目标。以下为落实这些要求的验证安排，尚未执行测试。

1. 少量 ESP32-S3 真机先验证 Wi-Fi 配网、屏幕扫码、手机 OIDC 登录、集市绑定生效、规范通问答及语音播放的完整链路。
2. 用不同账号和设备验证一账号多设备、单设备唯一归属、解绑后转交以及按归属账号检查规范通权限。新归属账号不能通过设备转交取得原账号的历史文字记录。
3. 验证客户可完成扫码绑定，但不能访问运营后台及管理 API；文字记录按账号和设备隔离、30 天到期清理，原始录音不作为历史记录持久保存。客户自助查看和删除页面不在首版验收范围。
4. 验证应用调用按集市规则计费、语音识别由平台承担、语音合成计入用户额度；结合集市契约验证失败和重试的计量与扣费。
5. 容量测试按少量真机联调、10、25、50、100 路并发逐级推进，并分别检查连接保持及同时语音对话。规模测试可在真机校准后使用兼容设备协议的模拟客户端，记录模拟与真机各自的覆盖范围。
6. 100 路语音测试必须覆盖设备接入、语音识别、规范通调用、语音合成和音频返回，不能用仅维持 100 个空闲连接替代。规范通和语音服务的限流与配额纳入同一验证链路。
7. 每阶段记录完成率、错误和断线、音频返回情况、首段语音等待时间、资源使用与计量一致性；用户未指定响应时间门槛，实际延迟作为观测结果报告。
8. OTA 先以一台真机验证固件上传、指定发布、设备下次检查更新、重启及目标版本回报，再验证一小批设备和发布范围隔离；升级后复验配网、设备归属及规范通对话。
9. OTA 验证只有获授权管理员能上传、发布、查询管理结果及重试；同时覆盖板型不匹配、离线设备、下载中断和升级结果未回报。已有发布的固件与目标版本应可追溯，新上传的同板型固件不能覆盖正在验证的发布目标。

阶梯节点是工程验证草案；100 台同时语音对话是已确认的最终目标，不因中间阶段通过而降低。当前尚未开始产品代码实现、生产部署或容量测试。

## 待接口和联调进一步明确

- OIDC、设备绑定、规范通及语音合成计费的正式接口与测试环境。
- 用户没有规范通权限或额度不足时的反馈与恢复方式；合成失败、重试或用户打断的扣费规则依据集市契约明确。
- 实际固件、样机、服务器和上游服务配额，以及运营人员对运行日志与对话内容的访问边界。
- 客户无需登录小智管理后台时，集市侧或独立绑定页如何提供原账号授权的解绑和转交流程；客户对话记录相关请求是否通过集市或其他渠道处理，尚未指定。
- 真实规范通结果中的长文本、引用或非文本输出怎样转为音箱可播内容，需结合实际应用响应确认。
- 实际固件的 OTA 检查时机、升级错误与版本回报、失败恢复能力，以及后台重试如何被设备下一次检查获取。

### 已有 OTA 能力与改造缺口

以下仍基于同一参考提交的只读代码检查，未进行真实固件升级。

- 原后台已有固件上传和型号、版本表单，上传 API 限超级管理员；同型号保存时会覆盖已有数据库记录，需要补齐可追溯的固件版本和发布记录。[上传接口](https://github.com/xinnan-tech/xiaozhi-esp32-server/blob/c8e60d1325650c8a31d00e36d8528f8bb74aeb11/main/manager-api/src/main/java/xiaozhi/modules/device/controller/OTAMagController.java#L245)、[保存逻辑](https://github.com/xinnan-tech/xiaozhi-esp32-server/blob/c8e60d1325650c8a31d00e36d8528f8bb74aeb11/main/manager-api/src/main/java/xiaozhi/modules/device/service/impl/OtaServiceImpl.java#L63)

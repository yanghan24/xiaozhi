# 音箱本机退出并解除绑定

2026-11-11 用户已明确确认：设置中的退出操作应释放本台归属，其他人无需原账号在手机授权，即可扫码绑定使用。决定见 [ADR-0008](../adr/0008-device-local-unbind.md)。

## 行为与协议

- 本机按钮显示「退出并解除绑定」，再次确认时说明其他账号可扫码接手。确认后立即停播，清除账号显示及旧二维码。
- 新固件使用 `POST /xiaozhi/device-control/v1/unbind`，以本台独立设备凭据鉴权，JSON 只含 `expected_permission_version`，值为当前已观察版本且至少为 1。成功 v1 `data` 精确包含 `permission_version: N+1`、`binding_state: "unbound"`。
- 后台在同一事务核对准入、凭据及许可版本，停用本台、清除归属、递增许可/归属代际及 revision、作废本台旧请求。重复请求只在当前仍未绑定且恰为 N+1 时返回相同已达成结果；重新绑定后旧请求必须返回 409，不能解除新归属。
- 后台返回不支持或拒绝时，不宣称已解绑；同版本仍保持本机停播，明确显示失败并允许用户重新确认重试。网络中断自动续作时始终使用原确认版本。
- 状态明确为未绑定后才撤去处理中状态，按最新许可取得正式 bind 二维码。新账号及原账号均可重新扫码绑定；同账号重新绑定也是新一代归属。
- 已经由旧接口退出、或需要原账号重新授权的已绑定设备，也能从设置执行本机解绑。不得将普通断网、授权失效或无积分自动当成解绑。
- 旧手机页面、旧 bind/resume 请求、旧语音 token、旧退出请求及旧账号资料读取结果不能影响或泄露到新归属。原账号其他音箱、共享授权、原有对话记录与设备接入凭据继续独立管理。
- 保留旧 `POST sign-out` 的停用语义；新接口与固件同时交付，不能仅更改旧接口或换一张恢复二维码。

## 验收边界

以现有真实 HTTP 控制/客户接口及固件控制工作线程为验证入口：覆盖 A 解绑后 B 可绑定、同账号重新绑定、重复和迟到请求、原账号页面围栏、停播/旧语音失效及第二台隔离。账号读取并发解绑不得泄露旧资料。固件还需验证旧服务不支持、失联及处理失败时保持停播，以及旧停用状态下仍可本机解绑。

配套 API 与公网精确路由先部署，再安装新固件；生产手机换账号绑定与两台音箱播放需再次实机验收。历史报告保留当时「退出后仅原账号恢复」的真实结果，不能将其改写为新行为已验收。

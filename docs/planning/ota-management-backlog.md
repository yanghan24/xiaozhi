# 后续 backlog：完整批量设备维护

2026-11-13 用户要求优先交付在线设备推送与后台显示/选择。下文为此前确认的完整范围历史快照，其中离线、空闲调度、停用/未绑定独立维护、配套固件和完整自动回报等扩展延期，不阻塞当前主线。当前有效规格为 [在线推送规格](ota-management-spec-draft.md)。

来源：#88批量OTA范围，复用已完成的#18。用户已确认固件来源、离线等待、忙碌等待及管理员维护权限；用户已确认完整范围及验收入口，按本规格实施。

## Problem Statement

运营管理员目前需要运维命令才能向指定音箱下发固件，无法在管理后台选择设备或安排全部兼容设备升级，也无法统一查看离线等待和实际安装结果。

## Solution

管理后台提供固件列表、设备选择及发布批次详情。从本项目GitHub Release导入明确版本并校验产物，选择单台、多台或全部兼容设备，预览目标与排除原因后确认发布。服务器固定目标集合，离线设备重连后继续、忙碌设备在本轮结束进入空闲后执行；按设备展示实际进度及安装结果。

运营管理员可维护未绑定或已退出停用的设备，但升级不能绑定账号、恢复语音许可或改变设备接入身份。维护操作必须由管理员授权、由已准入设备验证接入身份；设备被撤销准入不等同于客户退出停用。

## User Stories

1. 作为运营管理员，我希望从本项目GitHub Release导入并选择固件，以便使用确定且经过校验的产物。
2. 作为运营管理员，我希望看到板型、版本、构建标识和校验状态，以便选择匹配设备的固件。
3. 作为运营管理员，我希望选择一台或多台设备升级，以便控制发布对象。
4. 作为运营管理员，我希望选择全部兼容设备并预览名单，以便覆盖全部目标而不遗漏其他分页的设备。
5. 作为运营管理员，我希望看到已是目标版本和不兼容设备的排除原因，以便理解实际发布范围。
6. 作为运营管理员，我希望离线设备保留待升级任务，以便设备重新联网后继续。
7. 作为客户，我希望当前说话或播放完成后才升级，以免本轮使用被中断。
8. 作为运营管理员，我希望维护未绑定或停用设备，以便固件维护不依赖客户语音许可。
9. 作为客户，我希望升级保留归属、凭据和停用状态，以免维护改变账号关系或恢复已退出的使用许可。
10. 作为运营管理员，我希望逐台看到等待、升级中、成功、失败及结果待核对，以便判断实际结果而非仅看到已下发。
11. 作为运营管理员，我希望暂停尚未开始的目标，并在异常时保留证据，以便控制发布影响；未知执行结果不能自动重放。

## Implementation Decisions

- 复用现有管理界面组件、管理员认证及产品设备档案，发布目标由服务器计算并保存；“全部”不是当前页面全选，发布后新增设备不自动加入旧批次。
- GitHub Release导入固定资产字节、SHA-256、实际应用版本与ELF/构建标识，不能将同一个2.2.6版本字符串视为相同固件。预发布版本清楚标识，禁止静默追随latest。
- 本轮首先服务已有P4产品设备；校验板型/revision、布局和应用槽容量。在线/离线身份或硬件信息不足的设备显示待核验，执行前必须再校验，不猜测兼容性。
- 发布批次和逐台任务持久保存，服务重启不会丢失离线任务或重复已发送的操作。设备执行前再次检查发布仍有效、目标属于本台、产物兼容和本台空闲。
- 管理员维护通道与客户模型/MCP使用许可分离。停用设备只获得已获授权的固件维护能力，不获得语音资源调用能力；不跳过独立设备凭据和准入校验。
- 既有单台root维护工具不直接扩为批量调度器。评估旧后端草稿的发布、镜像校验及回报设计；补齐设备实际领取/空闲执行/结果回报与管理页面。现有固件若不支持所需协议，须交付配套固件及首次安装路径，并清楚列出可管理设备条件。
- 下载完成或下发成功不等于安装完成。使用实际运行产物和操作关联确认结果；回执丢失进入待核对，保存防重放记录。
- 暂停只影响尚未开始的任务，不中断Flash写入；没有操作证据时不能把未知结果变成可重试失败。实施时采用有上限的并发，避免全部设备同时开始下载。

## Testing Decisions

- 管理后台页面与实际管理HTTP接口：验证固件选择、单选/多选/全部、跨分页目标、预览排除原因、管理员权限、批次状态。沿用现有真实HTTP与权限过滤链测试。
- 设备OTA协议接口：验证本台身份/准入、离线重连、忙碌等待、暂停、服务重启持久化、实际安装回报及未知结果不重发。受控外部GitHub响应只用于自动回归，不冒充真实下载或安装。
- Ubuntu和真实P4：至少覆盖指定设备升级、未选设备不受影响、离线设备重连领取，以及停用/未绑定状态维护后仍保留原状态。固件安装使用真实重启、运行产物和身份证据，模拟结果不能替代。
- 只测试可观察的页面、HTTP/设备协议行为，不把内部方法调用次数当成验收。用户已确认上述测试入口，按这些接口开始测试驱动实现。

## Out of Scope

第一版不增加本地固件上传、任意第三方固件源、所有芯片型号支持、定时发布、强制同版本重装、自动降级/自动回滚、完整掉电故障矩阵或50路容量验收。既有客户问答功能与#19验收继续独立。

## Further Notes

用户提出的是管理能力建设，不是立即对现有全部设备执行OTA。本轮上线后先按指定设备验收；实际全设备发布另按明确选包和目标范围执行。

完整规格及验收入口已确认，已发布 [#95](https://github.com/yanghan24/xiaozhi/issues/95) 并关联#88。按固件目录、单台完整闭环、多设备批次、联合验收四个纵向切片实施；已有未提交草稿保持原样，仅择取适用实现。

# 管理后台选择设备及全部设备 OTA：需求梳理

2026-11-13 优先级更新：用户要求先交付全部在线设备主动推送、后台显示及选择，其余进入 backlog。下方访谈保留历史记录；当前范围以 [在线推送规格](ota-management-spec-draft.md) 为准，延期项见 [backlog](ota-management-backlog.md)。

日期：2026-11-13，Asia/Hong_Kong。来源：用户在 #18 完成后要求增加后台“选择哪台设备进行OTA，以及全部OTA”。这是 #88 中批量OTA范围的新交付切片，尚在梳理，不重开已完成的 #18。

## 已确认

- 后台支持选择设备升级，以及全部兼容设备升级。
- “全部”在点击发布时固定所有已登记且与所选固件兼容的目标设备；已是目标版本的设备跳过。
- 包含离线设备，保留待升级任务，重连后执行。
- 正在说话或播放的设备等本轮结束、进入空闲后升级。
- 后台显示各设备等待、升级中、成功和失败状态；成功必须依据实际安装结果，不能仅依据下发或下载成功。
- 固件来源为本项目GitHub Release，导入并校验后在版本列表中选择；第一版本不增加本地上传入口。
- 运营管理员可以维护已退出停用或未绑定客户账号的设备；维护权限与客户语音使用许可分开，升级后保留原来的停用和归属状态。

## 规格草稿

上述产品选择、完整范围和验收入口均已由用户确认。规格已发布为 [#95](https://github.com/yanghan24/xiaozhi/issues/95)，本地记录见 [规格](ota-management-spec-draft.md)。

## 现有事实与复用边界

- #18 / PR #92 已验证指定B通过当前产品语音会话调用设备维护工具的单次主动下发；同版本安装通过UART、切槽、ELF及重连证据确认。它没有批量目标、离线任务或管理页面。
- 既有管理页面包含上游固件上传/管理和按智能体加载的设备列表；不等于产品设备发布页面，当前页全选也不等于所有兼容设备。
- 旧工作区 `.worktrees/18-server-ota` 存在未提交后端草稿，保留原样。包含固件导入、明确设备列表的发布/暂停/重试、设备领取/回报、P4镜像及双槽兼容性检查等设计。
- 旧草稿采用设备主动领取，不会主动通知在线设备；需要核对实际固件的认证、领取和安装回报支持。#18的主动下发验收不证明另一条路径已可用。
- 旧草稿没有“全部”语义、产品设备候选/兼容性预览或产品OTA界面；不能直接部署为已完成功能。

## 待细化的设计要求

- 全部目标由服务器确定并保留预览/确认依据；显示不兼容及已是目标版本的排除原因。
- 固件/板型/revision/分区兼容性检查，权限与设备身份保持沿用项目约束。
- 明确离线等待、空闲等待、安装中、成功、失败以及结果待核对；未知结果不自动重复下发。
- 分批受控执行、暂停尚未开始的目标、服务重启后的持久任务恢复和实际安装回报，需要纳入后续规格。

本记录不是实施完成报告。没有向任何设备下发升级，没有改动现网服务。

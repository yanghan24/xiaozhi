## 2. #14 需要补的产品接线

在主线 `6bf7620`，`MarketModel.response_with_functions` 明确拒绝工具；产品连接强制 `nointent`，跳过 `UnifiedToolHandler` 构造。现有 MCP 客户端可用不代表产品入口已接通。

复用已有模型流式 `tools/tool_calls`、统一工具处理器和 `server_mcp`，按同一轮顺序完成：

```text
自然问题 → 当前设备许可与归属账号授权
         → qwen3.8-flash 自动选择 ask_knowledge
         → 再核对测试范围与当前许可 → 单次 MCP 请求
         → 核对协议错误、当前轮次与资料相关性
         → 模型依据资料续答／明确无相关资料或失败
         → Edge TTS → 当前设备播放
```

普通问题沿用同一产品入口直接回答。不要改成共享模型 Key 或旧管理员工具模式来绕过设备许可。模型、MCP、TTS 每次新调用及输出继续检查现有许可和归属；模型访问仍走正式 `model-access`。

### 结果进入模型前

1. 工具执行器将协议错误、显式工具错误、畸形结果映射为固定安全失败；合法结果的 `Action.REQLLM` 仅表示请求模型续答。
2. 当前 `chunks/generated=false` 是检索模式，`answer` 为组织后的原文。`status=ok`、来源和固定片段数均不能证明问题有答案。
3. 根据问题与片段内容检查相关性；无相关资料、资料不足或工具失败要明确反馈。有资料时核对最终回答是否由相关内容支持，来源留作核验，播报略过网址和引用编号。
4. 把资料作为数据处理，不能让检索内容覆盖系统指令、改变工具范围或索取凭据。资源链接不自动触发未验证的邻片／全库读取。

### 停止与迟到结果

沿用账号、设备、轮次、许可版本和归属代际，结果抵达及输出时再确认其仍属当前有效调用。打断／停用后拒绝新调用，丢弃旧轮次结果并停播；恢复只作用于目标设备的新轮次。

已有局部回归证明超时段不追加迟到结果、关闭后不提交、取消传播和未结束 worker 可继续回收，不能据此声称完整模型／TTS／设备围栏通过。远端取消能力未知；执行状态不明时不自动重放。

## 3. 一处完成真实模型与设备验收

由 #14/#19 在获准的同一台 P4 和同一测试账号下完成：

- 普通语音问题经麦克风、ASR、真实模型、Edge TTS 和扬声器完整播放。

- 一项工具失败或无相关资料的受控回归明确反馈；与真实成功链分开记录。
- 打断／本台停用后无新调用、无旧轮次结果或播放；恢复只恢复目标设备。

每轮保存服务／客户端／固件版本、脱敏账号与设备标签、识别／工具／模型／播放的关联、首段与完成耗时、实际通过／失败项目。直接工具脚本、合成 IO 和服务端生成音频各保留其证据边界。

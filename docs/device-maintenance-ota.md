# 开机联网的设备管理与 OTA

对应服务端需求 [#112](https://github.com/yanghan24/xiaozhi/issues/112)，固件基线为 A/B 已安装的 `12f2ff1b3e224ff012bdce95799ebf19740dcd11`。维护通道复用现有设备接入凭据及可信 HTTPS origin，不需要语音 WebSocket、客户绑定或本地语音使用许可。后台协议见服务端 `docs/development/device-maintenance-ota.md`。

设备完成网络发现后，在独立的 device-control 工作任务中轮流进行状态长轮询与 `POST /xiaozhi/device-control/v1/maintenance`，维护间隔约 20 秒；许可续期和停播确认优先。请求包含随机启动标识、OTA 能力、是否安全空闲，以及芯片、Flash、分区、应用 ELF、活动槽状态和精确板型。该投影不发送 Wi-Fi 名称、MAC、设备 UUID、屏幕信息或凭据正文。4.3 寸构建报告 `waveshare-esp32-p4-wifi6-touch-lcd-4.3`，其余构建保留原有板型。

只有当前应用槽为 `VALID` 才声明 OTA 能力。状态来自 `esp_ota_get_state_partition`；`PENDING_VERIFY` 为 `pending_verify`，其余状态为 `unknown`。管理请求返回 404 时继续正常的控制协议和语音；TLS 或设备认证失败仍按原有原则撤销本地语音访问。

## 领取与执行

服务器返回绑定当前启动标识的单次操作号、HTTPS 下载地址、bin SHA-256、目标 ELF SHA-256、精确字节数和到期时间。固件验证字段与可信 origin，再原子占有本机空闲门禁；说话、播放或录音中不会执行。正常停用或尚未绑定的设备完成启动后同样进入空闲状态，因此不依赖客户许可。

录音开始/恢复、音乐播放/恢复/切歌、语音处理启动，以及音频入队、解码和扬声器写入共用原子音频门禁。启动方从许可检查前到活动状态可见期间持有短期租约；已经出队的音频块持有到处理结束。维护只能在没有租约时冻结入口，再检查应用、录音、音乐及音频状态；失败立即解冻。因此不能在“许可已检查、尚未开始录音”或“队列已空、驱动仍在播放”的窗口抢占设备。执行前再次检查完整空闲状态。

本机先把操作号、原启动标识、目标摘要及 `accepted` 状态提交到 NVS，再发送 `accepted` 回执。等待服务端确认时，维护请求中的 `idle=true` 表示设备已独占安全空闲；普通唤醒和新的音频任务暂时被本机门禁阻止。收到同一操作的 `operation_ack` 且期限仍有效，才在应用主线程再次检查门禁、音频、网络及单调时钟，然后执行一次。旧 MCP 升级和维护升级共享同一个原子占用，不能同时写入 OTA 槽。

下载时检查精确 Content-Length、应用槽容量、图像头及目标 ELF，并对所有实际下载字节计算 SHA-256；截断、额外字节、错误 SHA/ELF、写入失败和 ESP-IDF 镜像校验失败均不切换启动分区，未完成的 OTA 句柄会被中止。操作期限限制开始写入；已经开始的写入不会仅因期限到达而被强行中断。只有所有检查通过及 `esp_ota_end` 成功后才设置启动分区并自动重启。

## 持久化及恢复

`ota_maint` 命名空间是维护账本，和 `device_ctrl` 一样不属于可清除的用户设置。正常恢复本机设置保留这两个命名空间；维护记录不保存签名下载 URL 或设备秘密。NVS 保存失败时禁用该次升级，不用内存记录替代已确认的持久保存。

重启发现旧 `accepted` 记录时不会重新下载或再次写入。实际运行 ELF 与目标一致且槽为 `VALID` 时报告 `installed`，否则报告 `interrupted`，均携带原启动标识。失败及重启结果在匹配的服务端确认前持续重报；确认后保留最后操作的防重记录。网络中断、超时或过期不能把未知操作转换为新的自动重试。

已持久保存、尚未确认的 `failed` 在重启后仍报告 `failed`，携带新请求的 `boot_id` 和原操作的 `origin_boot_id`。旧 `accepted` 确认不会触发重刷或清除该失败；只有匹配的 `failed` 确认才清账，后续重启继续保留已确认状态。

## 验证与交付边界

Ubuntu `jt@192.168.168.114` 上运行固件主机测试和 ESP-IDF 5.5.5 / RISC-V GCC 14.2 的真实 P4 交叉编译。原 4.3 寸、ESP32-P4 revision 3.1+、ESP32-C6 SDIO 与 `partitions/v2/16m.csv` 配置保留；私有 sdkconfig、签名资料和生成的固件不纳入 Git。

本轮新增公开协议及图像安装边界测试先红后绿；恢复本机设置保留维护账本的测试也先证实原逻辑失败再修复。40 项 CTest 覆盖领取确认、防重、重启结果、失败回执跨重启、并发音频启动与维护互斥、错误启动标识与 origin、过期、断网、存储失败、固件完整性、旧服务兼容，以及既有身份、音频和设备控制协议。`maintenance_tests --fixture` 生成真实 C++ 请求；`--accept-response <响应文件> <可信OTA origin>` 用生产协议类回放服务端响应并输出 `accepted` 请求，用于跨端 HTTP 互通验证。

这些结果不代替真实设备安装、重启及语音验收。A/B 仍运行旧固件，首次迁移需要通过现有维护方式安装新固件；安装后才具备不唤醒的管理 OTA。本轮没有刷写、复位或下发 A/B。

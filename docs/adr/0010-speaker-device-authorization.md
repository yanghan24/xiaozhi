# 音箱通过集市设备授权登录，运营后台仅供管理员

**现行范围**。音箱采用集市设备授权，后台仅供管理员使用。Java 保管授权与令牌，维护本台设备和账号归属。全局默认智能体在下一轮切换。当前功能与模块见[项目 README](../../README.md)。

## 决策与当期实施范围

2026-11-17 用户确认：音箱采用集市 device 应用和 RFC 8628；管理员后台不向客户开放。此决定替代 ADR-0003 的小智绑定网页与网站回调选型，保留 ADR-0005 的设备归属由小智维护、集市负责身份/权限/计费的职责。

本阶段范围同时调整 ADR-0001、ADR-0004 中 2026-11-10 的“本期 MCP 知识库”安排：先完成扫码授权、客户/设备关系、在线与默认角色，不自动带入历史固定知识库提示词、工具和仅允许特定账号/设备的限制。未来集市智能体或 MCP 扩展仍单独设计；当前小智的本地对话角色不等于接入某个集市智能体。

后台为已认证音箱管理扫码授权事务，保护 device_code、用户令牌和业务 Key；固件显示二维码及核对码，并同步设备状态。一个 Client ID 标识一个环境的接入应用，不标识物理设备。集市确认的 issuer + subject 关联客户；绑定时必须重查发起设备身份及归属代际，不能接受客户端自报用户。

单台退出、解绑与集市应用撤权分开。认证心跳独立于客户绑定和语音会话。暂时网络/续期故障不永久停用设备或撤销独立业务 Key。

管理员维护角色并明确设置初始默认角色。所有音箱暂时跟随默认角色；切换在当前回答完成后的下一轮生效并清空会话上下文。用户后续在音箱选择角色属于后续范围。

实施顺序、每阶段验证边界和未满足条件见 [第一阶段实施记录](../archive/completed/identity/speaker-phase1-implementation.md)。

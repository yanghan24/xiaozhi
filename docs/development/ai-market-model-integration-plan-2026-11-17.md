# AI 集市模型接入实施方案

状态：用户已确认，2026-11-17 开始实施。任务分支 `feat/market-model-integration`。
前置：恢复原版运行时的提交 `849d80e`（当前尚未合入 main）；本分支从最新 origin/main 创建后快进到该依赖，不修改 main。

## 范围与边界

- 保留小智原版音频接收、VAD、断句、对话、工具执行、上下文、TTS 和固件协议。
- 每个现有模型类型增加“AI 集市 / 小智系统”来源分组。集市提供一个稳定适配配置，管理员从兼容下拉列表选择模型；不批量导入远端模型为本地配置。
- 实际模型来自集市应用目录，按已实现协议、能力、已验证调用方式动态筛选，非固定的测试模型名单。保存和运行时均校验，不能通过直接请求绕过。
- 原版功能完整保留。Intent 的 function_call 模式继续使用主 LLM；独立意图可选择集市模型。Memory 保留原版记忆模式，集市仅承担其中的总结计算。
- VAD、TTS、RAG 不扩展集市适配。TTS 继续使用现有系统提供者和音色。不开启向量/重排、复杂记忆或其他语音协议。
- ASR 只适配 `spark_zh_iat_new`、协议 `xfyun_asr_v2`；单轮音频最多 60 秒。不接 rtasr-llm 或异步文件转写。
- 不修改 AI 集市、114 或固件，不部署、不刷机、不合并 main。开发和验证在现有 xiaozhi-dev，数据仅用 104 小智独立开发库。
- 所有秘密保存在 runtime 私有配置或加密授权存储，不提交、不传给浏览器或固件。已有测试 Key 仅用于限定真实验证，不固化为产品公共 Key。

## 兼容规则

目录的 capabilities 与 verifiedCapabilities 均须满足用途；protocol 必须在已实现范围内。

| 用途 | 筛选 |
| --- | --- |
| LLM | openai + chat + streaming；角色使用 function_call 时还要求 tools |
| VLLM | openai + chat + vision，verifiedMethods.vision 包含 chat-image-data-uri |
| 独立 Intent | openai + chat + streaming + structured-output，已验证 JSON 调用方式 |
| Memory 总结 / SLM | openai + chat + streaming；需要 JSON 的模式采用更严格约束并解析校验 |
| ASR | transcription + xfyun_asr_v2 + publicId=spark_zh_iat_new |
| VAD/TTS/RAG | 无集市候选，保留系统配置 |

模型请求使用 publicId，内部 UUID 仅作目录标识。目录不是单用户的资源授权；实际调用仍由集市校验用户、Key、权限及积分。
目录查询失败不得清空已保存配置或自动换模型。已选择模型不可用时明确报错，由管理员处理。

## 应用与凭据

- 网站后端 Client ID/Secret 使用 client_credentials、models:read 获取短期目录令牌。仅复用令牌，目录按需读取，遵循 no-store；401 仅重新申请令牌重试一次。
- 音箱使用原 device 客户端扫码授权。用户已确认集市权限开放；请求 credentials:manage，由用户授权领取应用专用资源 Key。
- 用户登录、设备绑定与模型调用资格分别处理。选用集市模型时才要求资源 Key，不因取 Key 失败取消已经完成的绑定。
- 按设备/会话确定归属用户，加密保存资源 Key，按连接生成独立配置。不污染共享模型缓存或跨用户共用带 Key 的实例。
- 配置注入不增加每帧、每 token 的远程查询；Python 对话/视觉/独立意图及 Java 总结/标题都遵守同一用户归属。
- Key 失效、权限不足、余额不足、服务异常明确失败，不自动借用公共 Key 或切换其他模型。

## 分阶段提交

1. P0：本方案和阶段记录，先提交。
2. P1：独立目录客户端、兼容规则、稳定适配配置及管理员设置接口。测试令牌隔离、分页、能力筛选、错误和配置保存校验。
3. P2：原版 ASRProviderBase 下增加 xfyun_asr_v2 提供者。复用原版入口，处理首帧缓存、序号、动态修正、VAD/手动结束、最终结果和取消清理。只测试该协议。
4. P3：用户 Key 获取、加密存储和按用户注入原版配置，覆盖 Python 和 Java 辅助调用。验证多用户隔离、权限撤销、无 Key 时身份仍独立。
5. P4：复用 Element UI 与当前页面风格，实现来源分组和兼容模型选择，保留原角色配置及系统模型功能。
6. P5：限定的开发联调、必要真实模型检查与交付记录。每个阶段先通过相关检查再单独提交，不扩大为全量测试或其他环境变更。

## 验证依据与验收

2026-11-17 已完成真实网关验证：指定的 deepseek-v4.1-flash、glm-5.3、qwen3.8-max、glm-5.3-flash、qwen3.8-flash、kimi-k3.1-pro 均通过原版 Python 提供者的流式聊天和测试工具往返。
qwen3.8-flash 另通过视觉、提示词 JSON 意图、摘要；ASR V2.0 通过一段 2.345 秒固定语音。
这些是接口兼容样本，不是固定名单或稳定性/准确率背书。脱敏证据在私有 runtime/xiaozhi/reports/model-access-20261117/。

实施后的定向验证：
- 协议替身验证选项筛选、来源分组、管理员保存、凭据隔离、ASR 重复/替换结果、开始/结束/超时/取消。
- 使用独立开发库的临时数据验证选定适配配置进入原版音箱链路，用后清理并恢复原默认设置。
- 真实检查只用已授权测试 Key 和选定模型，限制次数；不遍历所有候选。
- 自动领取 Key 需要实际扫码用户参与时如实列出待验收项，测试 Key 直连不能冒充授权链路通过。
- 真机拾音、播放、打断和重连由单独的 Ubuntu 实机验收安排覆盖，不以开发模拟替代。

# 原版链路恢复与第一批固件实施方案

记录日期：2026-11-17。

状态：用户已确认目标、阶段边界及固件分批原则，本文件完整记录实施方案。本次仅新增文档，尚未实施本方案中的代码修改、构建、部署或刷机；既有版本的测试结果不能作为恢复版本的验收结果。

## 1. 目标与阶段边界

本轮以官方原版为依据，恢复小智音箱完整运行链路，并将管理员后台、集市用户身份和设备管理按职责接入。现有代码和既有提交不自动构成保留实现的理由，需要逐项对照迁移。

用户确认的边界：

1. 恢复所有原版调用链路和配置加载能力，范围不限于 ASR、大模型和 TTS。
2. AI 集市应用接入负责扫码登录、用户身份与资料、用户和设备绑定、退出及解绑等。集市模型目录和模型调用属于下一阶段。
3. 设备管理负责设备信息、型号、固件版本、心跳、在线和固件升级；设备归属与用户管理关联展示。
4. 114 仅参考需要筛选的角色、提示词和 MCP 配置资产，不参考其设计、实现、部署方式或特殊账号/设备规则。当前已有功能另做迁移分析。
5. 固件按照三批处理，本轮只做第一批。第一批交付后等待用户真机验证，未经后续安排不开始第二、三批。
6. 不为本轮恢复提前实现集市模型列表、模型协议适配、用户模型 Key 注入及相关模型计费处理。

“恢复原版”是恢复原版支持的能力及其配置生效逻辑，按实际配置启用；不强制同时启用所有模型、记忆、插件、视觉或其他能力，也不重新开放客户登录管理后台。

## 4. 服务端完整链路恢复

### 4.1 恢复清单

| 修改范围 | 具体工作 |
| --- | --- |
| 连接与配置 | 恢复原版连接处理、配置获取、提供者初始化、连接清理和原版支持的通信通道 |
| 音频输入 | 恢复唤醒、问候、开始/停止监听、VAD、音频接收、缓存及 ASR 接口，保留真正的流式识别能力 |
| 对话与模型 | 恢复原版上下文、系统提示词、普通及连续对话、模型适配、参数加载、流式输出、意图识别和函数调用 |
| TTS 与输出 | 恢复分句、合成队列、编码、音频发送节奏、字幕和播放状态，避免普通回答等待全文生成后才进入 TTS |
| 中断与退出 | 恢复打断、取消在途任务、清理旧音频、退出指令、断线重连和会话关闭 |
| 高级配置 | 恢复记忆、上下文源、声纹、视觉、插件、RAG 等原版支持配置的加载和启停逻辑 |
| 工具机制 | 恢复服务端 MCP、设备 MCP、插件及其他原版工具入口，解除知识库专用处理的固定限制 |
| 记录与异常 | 核对对话上报、历史记录、错误处理、后台任务与资源释放 |

原版 ASR 提供者既有流式也有非流式实现，按所选提供者行为工作。不能只因接口使用 WebSocket 就认定实现为实时流式，也不能把某个厂商的地址替换成集市地址就认为协议已兼容。

### 4.2 当前偏离的处理原则

- 当前 `product_asr.py`、`product_chat.py`、`product_voice.py`、`product_role.py`、`product_knowledge.py` 等定制链路不作为新实现基础。核对调用点后，正式运行入口回归原版扩展点，不保留第二套并行对话处理器。
- 核对 WebSocket 入口、ConnectionHandler、音频收发、listen/abort 处理、TTS 基类及工具处理器中的定制分支，避免只删除入口而遗漏底层行为。
- 当前配置虽然能保存，但只使用部分字段的情况必须逐项修正。每个恢复配置项要能追踪到语音运行模块。
- 退出、解绑及设备停用仍需有效执行，但权限控制与原版生命周期结合，不在每个音频块或模型输出片段中同步远程查询数据库。
- 不用已有定制测试的数量证明恢复完成；重新围绕原版接口和实际需求做匹配的定向验证。

## 5. 集市应用接入与模型调用解耦

### 5.1 本轮范围

- 音箱发起扫码登录，后台完成集市 device 授权事务、用户身份校验及授权状态管理。
- 同步用户及组织资料，维护唯一设备归属，支持用户与多台设备关联。
- 处理登录状态、本台退出、退出并解绑、重新扫码及重新绑定。
- 管理端展示客户资料、设备数量及在线状态；资料或余额暂时无法查询时明确显示状态，不作为绑定条件。
- 将有效设备身份、绑定关系和管理员启停状态衔接到原版语音连接。
- 新连接及必要业务边界校验设备使用资格，退出、解绑、停用后终止相关会话，不允许旧身份继续使用新归属设备。

### 5.2 必须解除的现有耦合

当前实现会在登录绑定过程中领取集市模型调用 Key，并将 Key 是否有效作为语音可用条件。本轮须解除这一前提，重新区分用户身份授权、设备归属、设备准入和模型资源调用。

用户绑定成功不要求先取得集市模型 Key。原版语音可通过管理员明确配置的原版提供者及相应凭据验证，不因尚未接入集市模型目录而无法运行。用户集市应用授权令牌与管理员配置的模型凭据分别管理。

本轮不自动领取模型 Key、不同步集市模型目录、不适配集市模型协议、不把集市模型 Key 注入 ASR/LLM/TTS。已有授权和模型凭据数据不因代码调整被随意删除；必要的数据迁移和回退边界单列说明，不在新运行链路中继续依赖。

## 6. 管理后台与功能迁移

页面遵循现有 UI 风格，优先复用原版页面及当前前端组件。

| 功能 | 修改与迁移方式 |
| --- | --- |
| 智能体管理 | 保留原版完整新增、编辑、模板、模型/音色选择、试听、声音参数、标签、高级配置和版本历史，逐项接通运行时 |
| 默认智能体 | 管理员明确设置初始默认，未设置时不进入正常对话；允许新增、编辑和切换，当前回答先完成，下一轮采用新角色并清空旧上下文 |
| 用户管理 | 展示集市用户、组织关系、绑定设备数量和在线状态；详情展示资料、绑定关系、余额查询状态及设备信息 |
| 设备管理 | 设备档案、标识、型号、固件版本、心跳、在线、启停；用户归属提供关联查询，不复制一套用户管理 |
| 固件管理 | 统一固件来源，以原版管理及升级流程为基础，处理当前 `ai_ota` 与 `dc_ota_firmware` 两套目录的衔接，避免同一固件重复管理 |
| MCP 管理 | 独立维护 MCP 服务、地址、传输方式、认证配置、工具目录、连接/同步状态和引用关系；智能体选择关联的服务及允许工具 |
| 系统设置 | 沿用已确认的菜单框架，将管理员及系统配置与客户、设备关系分开 |

模型启用和默认等原版配置语义需保持可解释、实际生效。本轮不增加集市模型同步按钮或目录分类接口。

设备在线独立于语音会话在线，不能用是否唤醒语音判断设备是否联网。固件升级和设备维护不应改变用户归属或替用户完成登录。

当前批量发布、待机升级、专用烧录交付及复杂恢复流程作为扩展功能逐项登记，不默认保留其设计或实现。本轮以第一批规定的原版升级闭环为交付范围。

## 7. 两类 MCP 与 114 资产使用范围

### 7.1 两类 MCP

| 类型 | 含义与处理方式 |
| --- | --- |
| 服务端 MCP | 外部知识库等服务提供工具，后台维护连接和认证配置，语音服务按智能体配置调用 |
| 设备 MCP | 官方固件已有的设备工具，通过设备连接发现和执行，例如状态查询、音量、亮度、主题以及硬件支持时的摄像头操作 |

设备工具不要求管理员逐台手工录入。重启、升级等原版用户专用工具须保留相应权限边界，不能把全部维护工具直接交给模型自由调用。

MCP 管理只负责服务配置和目录，工具执行仍进入原版机制；增加菜单不代表自动完成调用链路。工具发现、关联、实际调用与结果处理分别核对，不能把原版通用工具处理又收缩成固定 `ask_knowledge` 分支。MCP 认证配置独立管理，不借本轮接通集市模型 Key；需要下一阶段资源凭据的接入明确标记依赖。

### 7.2 114 只参考资产

可筛选内容：角色名称、角色提示词、对话规则、MCP 服务地址/传输方式及必要配置资料。

这些内容先整理为候选，由管理员决定新增、编辑及默认设置。不得自动搬入旧环境的五模式切换行为、固定模型/音色、指定账号/设备白名单、授权判断、工具编排、私有运行配置或旧部署方式。

MCP 密钥、用户令牌和其他秘密不写入文档、源码或提示词。资产登记不等于复制 114 的用户授权或将开发环境连接到其依赖。

## 8. 固件三批迁移安排

### 8.1 第一批：本轮实施

目标为原版完整音箱能力，加上必要的扫码绑定及基础设备维护。

| 内容 | 实施要求 |
| --- | --- |
| P4 硬件 | 核对板型、屏幕、触摸、音频编解码器、麦克风、扬声器、引脚和实际资源布局，保留硬件必需适配 |
| 核心交互 | 恢复原版配网、唤醒、监听、上传、播放、打断、状态提示、连接及重连 |
| 设备 MCP | 恢复官方工具框架及实际硬件支持的基础工具 |
| 登录展示 | 必要的二维码、核对码、登录状态、过期/拒绝提示及重新扫码入口 |
| 本机解绑 | 明确确认后结束交互、解除本台绑定并允许重新登录，不影响其他设备 |
| 设备身份和心跳 | 稳定设备标识、必要认证、心跳、型号及版本上报；不依赖语音连接维持设备在线 |
| OTA | 检查版本、下载、安装、重启及重新连接；复用原版设备升级执行能力 |
| 本机重置 | 明确配网重置、恢复出厂和后台解绑的语义，避免通过清理设置意外改变设备身份或归属 |

逐项替换主程序、音频和 WebSocket 中的复杂定制控制分支，必要业务扩展集中实现，不继承整套旧许可/维护体系。保留原版正常打断、任务生命周期及设备操作边界。

保持当前明确的板型和分区布局，不以恢复原版为由整片擦写或变更分区。必须变更的硬件适配或存储语义单列原因及影响，不能隐含在功能移植中。

### 8.2 第二批：真机验证后另行安排

轻量展示资产，包括公司 Logo、名称、配色、简单时钟/日期及进一步的账号资料展示。第一批登录所需的最小账号状态与扫码界面属于第一批，不因第二批推迟而缺失。

迁移展示资产不意味着恢复整套定制待机仪表盘及其内部控制实现。

### 8.3 第三批：真机验证后逐项确认

| 额外功能 | 延后原因 |
| --- | --- |
| 本地音乐播放器 | 争用扬声器，需要独立处理与对话的音频优先级 |
| 保存录音到 SD 卡 | 涉及麦克风、存储、后台任务和明确的业务用途 |
| 番茄钟 | 涉及计时、提示音及对话交互 |
| 天气、定位、空气质量 | 增加外部请求、密钥、缓存及刷新任务 |
| 专用日历页面 | 属于额外产品功能 |
| IoT 遥测 | 增加另一套服务连接、凭据和上报逻辑 |
| SD 存储及相关页面 | 随真正需要的音乐/录音等功能评估，不为第一批额外引入 |
| 复杂交付、身份修复、批量/待机 OTA 扩展 | 独立核查必要性、依赖和恢复风险 |

这里的录音指额外保存录音文件，不包括原版语音对话必需的麦克风采集。暂缓设备天气页面不删除原版通过服务端工具回答天气问题的能力。

第二、三批源码和资产保留，第一批运行版不带入这些额外功能。不得未经用户后续安排而顺带迁入、删除或开始实施。

## 10. 开发环境与验证边界

- Git、工具、依赖安装、构建和开发检查全部在独立 `xiaozhi-dev` Dev Container 中执行；宿主机不安装工具或依赖。
- 使用小智专属 Docker 卷保存依赖、缓存和构建产物，容器临时文件和日志位于 `/opt/xiaozhi-dev`。
- 开发数据库和 Redis 使用 104 上的小智独立实例。AI 集市代码和文档只读参考，不修改其文件、服务、容器、数据库或配置。
- 私有配置和访问资料放在 `/home/timyai/dev/runtime/xiaozhi/`，不提交秘密。
- 本地专用部署配置使用 `deploy/local-zhou`，不覆盖同事的 `deploy/local`。
- 114 是独立部署/实机环境，不作为开发依赖。本方案记录及开发检查不授权修改其服务、数据库或配置。

定向验证包括原版配置加载和生效、流式/非流式 ASR 接口、模型到 TTS 的逐段传递、打断取消、音频队列、断线重连、用户设备关系、默认智能体切换、心跳、工具与 OTA 协议。

外部模型、TTS、MCP 的真实调用与协议替身分开记录，不用替身成功证明真实服务可用。验证只覆盖本轮变更和必需链路，不扩大到压力测试、全部提供者逐一付费调用或无关故障矩阵。

性能记录按说话结束、ASR 完成、模型首字、首段合成、首音发送/实际播放分别标记；区分代码推导、开发计时与真机观察，不凭感觉承诺响应速度。

## 11. 交付与真机验收

交付应包含：

1. 服务端与固件固定源码提交及配套关系。
2. 第一批 P4 应用镜像、SHA-256、版本、板型、分区兼容说明。
3. 原版链路恢复清单、现有功能迁移状态及已知限制。
4. 开发测试和构建证据，外部服务真实验证与模拟验证分别说明。
5. 对应源码/配置的恢复说明，不用 Git 回退冒充数据库或设备 Flash 恢复。
6. 真机验收步骤、服务端部署条件和结果记录位置。

安排实机测试前遵守 [CONTRIBUTING.md 的测试环境政策](../../CONTRIBUTING.md#测试环境)，先确认明确授权的 Ubuntu 环境、服务版本、设备板型/固件、可达地址及原版提供者所需凭据。开发构建通过不代表已经授权部署或刷机；涉及具体环境或设备时按用户授权执行。

真机重点验收：配网、扫码登录、普通完整问答、第一声响应、打断、连续对话、退出解绑、重新绑定、重启与断线恢复、设备在线与心跳、音量/亮度等工具、OTA 下载安装及重启后恢复。

## 12. 停止条件与后续阶段

第一批交付后停止功能扩展，等待用户真机验证。用户反馈的问题只在第一批已确认范围内修复；第二、三批须在用户后续安排后继续。

后续集市模型阶段再实现模型目录获取和分类、协议适配、用户专用 Key 注入、模型权限、余额/计费及资源错误处理。不得提前以本轮恢复为由完成或重新引入这部分依赖。

## 13. 与既有记录的关系

本方案记录用户最新边界。此前 [speaker-phase1-implementation.md](speaker-phase1-implementation.md)、[agent-ui-restoration.md](agent-ui-restoration.md) 及部署/验收材料保留其历史范围，不用旧方案中“产品语音专用链路”“绑定需要模型 Key”等实现约束覆盖本次决定。

# 模型兼容性、智能体分组与服务管理实施方案

2026-11-17，依据用户确认的待修改清单实施。分支从最新 origin/main 创建，快进承接尚未合入主线的管理弹框及此前功能。

## 阶段与提交

1. 模型兼容性：主 LLM 要求 openai、chat、streaming、tools，声明和验证均满足；Memory 仍按摘要用途，不强加工具；SLM 保留原版复用 LLM 配置方式；Intent/VLLM/ASR 保持各自协议及已验证方式限制。列表、保存、角色和运行时共用规则；能力标签按已验证交集显示，删除“仅普通聊天”。补针对性兼容测试。
2. 智能体模型下拉：AI 集市优先、小智系统其次，各类型始终显示两组；空组显示不可选“无”。保留现有模型、音色联动与意图/记忆配置，不批量导入远端模型。
3. 服务地址与管理：server.websocket 作为统一设备连接地址来源；将开发私有 speaker.voice-url 一次性迁移到该参数后移除独立来源。服务管理与设备状态下发使用同一解析组件；过滤 null/空项、校验地址，明确未配置与未检测状态。若需要内外网差异，使用显式运维地址映射，不作为第二份设备地址。
4. 运维通道：管理员 API 保留权限及确认，使用独立服务管理 WebSocket 路径和服务间认证，不伪造设备或绕过音箱鉴权。Python 管理处理只执行 update_config/restart，不进入音频、模型或会话初始化。校验请求/响应动作与真实回执，失败不报成功。原版设备语音和 OTA 执行流程保持。
5. 定向开发验证与交付：Java/Python 管理通道用本地协议替身及重启函数替身验证，绝不向现有语音服务发送重启或配置刷新。浏览器拦截模拟写入检查布局及事件；仅必要开发 API 打包更新。每阶段单独本地提交，记录证据。

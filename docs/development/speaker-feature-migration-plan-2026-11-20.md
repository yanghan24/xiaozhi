# 小智第三方服务、MCP 与固件功能迁移方案

记录日期为 2026-11-20。本轮实施第三方服务配置管理、固件基础界面、日历和番茄钟。天气取数、天气 MCP、SD 卡、本地音乐和录音留待后续阶段。

## 1. 基线与范围

- 开发基线为服务端 `81eac33` 和 Waveshare P4X 4.3 寸固件 `f9a130a`（v2.6.3）。固件沿用官方 v2.6.0 的板型、分区及语音路径，并保留现有扫码绑定、心跳和 OTA。真机验收另记设备实际运行版本。
- 服务端沿用现有 Vue 管理页面、Java 管理 API、Python 语音服务及通用 MCP 调用。原有语音链路继续负责唤醒、收音、ASR、大模型、工具调用、TTS、打断和重连。
- 从旧固件参考品牌、页面布局和具体功能。新增页面和功能在当前固件中各自接入，按功能逐项迁移。旧 JetLinks 遥测从本次范围移除，设备在线及对话记录沿用小智现有能力。复杂维护、批量与待机 OTA 扩展另行评估。

本方案细化原迁移计划中的第二批和第三批功能。[原分批计划](upstream-restoration-phase1-plan-2026-11-17.md#8-固件三批迁移安排) · [语音链路与身份边界](../adr/0011-restore-upstream-runtime-and-separate-identity.md)

## 2. 总体分工

| 入口或模块 | 职责 |
| --- | --- |
| Vue 管理页面 | 在「系统设置 → 第三方服务」管理供应商配置。在「MCP 管理」登记 MCP 服务，并在智能体设置中选择关联。 |
| Java 管理 API | 统一管理第三方服务地址、凭据及启用状态。业务接入阶段增加位置解析、天气与空气质量取数、缓存，以及供设备和天气 MCP 使用的接口。 |
| Python 语音服务 | 沿用现有通用 MCP 客户端发现和调用工具，结果交回模型生成回答，再按现有 TTS 链路播报。 |
| 天气 MCP 服务 | 根据问题和已鉴权的会话确定城市，调用 Java API 的取数能力，将查询结果返回语音服务。 |
| 小智音箱 | 待机天气数据通过小智设备接口获取。显示层读取本机状态或模块缓存，分别管理待机、对话及各功能页面。 |

```text
待机屏 → 小智 Java 设备接口 → Java 第三方服务 → 已选供应商
语音问答 → Python 通用 MCP 客户端 → 天气 MCP → Java 第三方服务 → 已选供应商
```

待机屏按现有设备认证和绑定的 AI 集市账号获得访问权限。两条链路共用设备位置、供应商配置和取数能力，第三方凭据留在服务端。

在「系统设置」增加「第三方服务」Tab，复用现有前端组件、表单和编辑弹框。每家服务登记一次，可以配置多个接口，共用的凭据配置一次。页面管理服务名称、用途、地址、认证方式、启用状态和凭据配置状态。Java API 加密保存凭据，编辑和列表页面只显示是否已配置。

以下是先纳入管理的服务。地址和路径用于登记及历史核对，实际使用的供应商、地址和凭据由配置和后续方案确定。

| 服务 | 接口和用途 | 认证 |
| --- | --- | --- |
| 高德 | `https://restapi.amap.com/v3/ip` 用于 IP 粗定位。`https://restapi.amap.com/v3/weather/weatherInfo` 按行政区划码查天气、温度、湿度、风向和风力。 | 共用高德 Web 服务 API Key。旧固件通过 URL 的 `key` 参数传递。 |
| 和风 | `https://<api_host>/geo/v2/city/lookup` 用于城市查询。`/v7/weather/now` 和 `/v7/weather/7d` 用于实况与七天预报。 | 共用一个 API Host 和 Key。旧 Python 插件通过 URL 的 `key` 参数传递。 |
| 太平洋电脑网 | `https://whois.pconline.com.cn/ipJson.jsp` 用于通过 IP 推断城市，旧语音天气在用户未指定城市时使用。 | 旧调用只传 `json` 和 `ip` 参数。 |

## 4. MCP 服务接入

1. 新增天气 MCP，沿用现有「MCP 管理」登记服务地址和认证，再由智能体配置选择关联。知识中心等既有服务，以及后续新增 MCP，都沿用同一套登记、发现和调用机制。
2. 天气 MCP 复用 Java 第三方服务的取数接口。Python 负责通用 MCP 调用，天气供应商选择、位置计算和凭据处理由对应服务承担。
3. 明确指定城市的请求优先按所指定城市处理。用户问「我这里」时，由天气 MCP 根据可信会话查设备城市，与待机屏共用同一份位置配置。设备没有城市时，可以查账号默认城市。两处都没有可用位置，再让智能体询问城市。
4. 当前 MCP 配置按智能体下发。实现设备定位时，复用 Java 的差异化配置下发和 MCP 客户端已有的认证头能力，为天气 MCP 附上限定会话及用途的短期凭据。天气 MCP 验证凭据后查询账号和设备位置。模型工具参数用于提供用户指定的地点，设备及账号身份来自已校验的会话。

「第三方服务」保存供应商配置，「MCP 管理」保存工具服务配置，智能体关联决定工具的可用范围。天气 MCP 的部署形式在接入阶段确定。现有 Python `get_weather` 插件仍是旧天气能力，切换时按智能体核对天气工具选择。[现有 MCP 配置下发](../../main/manager-api/src/main/java/xiaozhi/modules/config/controller/ConfigController.java) · [现有 MCP 客户端](../../main/xiaozhi-server/core/providers/tools/server_mcp/mcp_client.py)

## 5. 固件功能模块

每个模块管理自己的状态和资源。页面从对应模块读取状态，并将用户操作交给模块执行。网络、SD 卡读写和媒体解码在各自任务处理，显示线程和原有语音处理按现有职责运行。

| 模块 | 方案 | 与语音的关系 |
| --- | --- | --- |
| 品牌与待机展示 | 恢复公司 Logo、产品名称、配色、时钟和日期。用现有系统时间和校时结果刷新。 | 待机页按现有设备状态呈现。配网、扫码、对话、错误提示和升级沿用现有视图及优先级。 |
| 账号资料 | 复用账号模块的绑定状态和显示名，补充已登录时的展示。 | 扫码、登录和退出继续走现有账号页面。 |
| 日历 | 单独实现 LVGL 页面，使用本机系统时间和日历计算。 | 页面负责导航和显示。 |
| 番茄钟 | 独立页面和本地计时模块。复用现有提示音能力。 | 对话中到点先显示提醒，语音空闲后再播放提示音。 |
| 天气、定位和空气质量 | 独立刷新模块通过小智 Java 设备接口取数并缓存。待机卡片读取缓存，按最近数据的状态显示。 | 刷新放在后台，超时或离线时天气卡片显示对应状态，语音继续按既有链路运行。 |
| SD 卡与本地音乐 | SD 卡挂载和文件访问统一由板级存储模块管理。音乐模块负责读取、解码和播放本地文件，使用统一音频输出入口。 | 对话优先使用扬声器。发起对话时先让出本地音乐的输出。播放音乐时的唤醒与切换表现单独做真机验收。 |
| 本地录音 | 为 P4X 新建录音页，用户明确开始和停止，录音保存到 SD 卡，文件写入和收尾由录音模块负责。 | 录音期间麦克风专用于录音。用户先停止并释放麦克风，再恢复待机和语音唤醒。 |

本地音乐、录音和提示音集中通过音频边界接入。开发时沿用当前 `AudioService` 和原有状态机的语音工作方式，具体媒体接入按模块单独验收。旧源码 `70550a5` 的独立录音页属于立创 S3 的功能容器，P4X 按自己的布局新增触屏入口。[历史页面核对](../verification/2026-11-10-p4-ui-recovery.md)

## 6. 固件 UI 与语音反馈

继续使用 v2.6.1 的 C++、LVGL、`LcdDisplay`、现有主题和 P4X 显示驱动。待机页的布局、数字时钟、Logo、配色和功能入口尽量贴近旧版。新增页面分别管理创建、显示、退出和状态刷新。状态更新沿用当前设备状态和 `Display` 接口，原先集中在 `StandbyDashboard` 的新增功能按各自页面组织。[旧 UI 核对](../verification/2026-11-10-p4-ui-recovery.md#原因与对照依据)

| 阶段 | 界面反馈 |
| --- | --- |
| 已唤醒、连接中 | 识别到唤醒词后立即给简短的视觉反馈。建立连接期间显示「正在连接」。 |
| 开始收音 | 按现有收音状态显示「正在听」和对应动画，提示用户可以说话。 |
| 识别结果返回 | 显示识别到的用户文字。等待回答时提供「正在处理」反馈。 |
| 回答和字幕 | 沿用现有播报状态和分句字幕消息。旧 Logo 动画样式可用于这一阶段。 |
| 播完、打断和出错 | 跟随现有状态回到聆听或待机。打断时结束旧动画，错误提示按现有优先级显示。 |

现有 `tts.start` 可能紧跟识别结果发出，早于扬声器实际播放。**这一轮只使用现有状态和事件。设备首帧通知及动画与实际音频的精确同步暂缓，后续单独设计。** [现有事件顺序](../../main/xiaozhi-server/core/handle/sendAudioHandle.py)

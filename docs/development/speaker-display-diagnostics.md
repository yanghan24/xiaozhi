# P4X 对话动效和 LCD 诊断

2.6.9 实机在对话中偶发整屏闪蓝。LCD 扫描供数不足是当前排查方向，需由驱动事件验证。

1. 对话波带集中在底部 60 像素，以约 12 帧每秒绘制主波纹。连接与等待期间保持静止，收音及实际播报期间播放。开机、首页和屏保沿用其静态效果。
2. 在 P4X 显示驱动的 `underrun` 中断分支累计事件，定期记录对话显示状态、波带是否绘制及所处心跳窗口。音箱继续使用现有设备诊断开关、30 分钟有效期、鉴权心跳和日志批次。
3. 管理 API 继续接受旧固件的报告，设备详情增加 LCD 诊断事件的显示。按管理 API 与页面、OTA 应用固件的顺序发布。

开发检查覆盖波带区域、频率与状态切换，缺帧汇总、超时、重试及旧日志兼容。真机升级和闪蓝复查分别记录。

## 2.6.11 对话波带和 TTS 播放诊断

对话波带恢复 2.6.9 的 800×134 区域、主波纹、填充及光晕，去掉第二条细线。动画每 84 毫秒更新，连接和等待时静止。保留 2.6.10 及其制品作为对照基线。

2.6.10 的实机日志曾出现服务端已发送 TTS，音箱继续心跳但停在播报状态的情况。沿用现有诊断开关，在每个心跳窗口汇总设备侧播放指令、音频收包、丢包、解码、输出任务、声卡写入结果及停止或断线收尾，不等待一轮对话正常结束。管理端先支持新的结构化诊断，再发布应用固件。

每批记录各阶段的次数、最近一次发生时的开机后毫秒数和对应结果。原有「首次写入音频输出」记录的是首包抵达输出任务的时间。新增的「声卡写入成功」才对应驱动返回成功。编解码器写入超过 1 秒未返回时，诊断会上报采样时的持续时间。诊断数据只包含播放过程的计数、状态和结果码。

## 2.6.12 波带恢复与 TTS 收发核对

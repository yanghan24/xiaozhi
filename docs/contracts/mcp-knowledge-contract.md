### 3.1 已实现的通用 MCP 安全边界

- `None`、明显不符合结果结构、渲染失败或明确 MCP 工具错误，返回固定 `Action.ERROR`，不把错误正文交给模型。
- 同时核对 `is_error` 和兼容命名 `isError`；存在的标记必须是布尔 False。别名矛盾、非布尔值或 True 都不当作正常结果。
- `content` 要为列表；非空时只校验内容块基本 type。空列表配合字典型 `structured_content/structuredContent` 可以正常回传，不误拒合法 structured-only 结果。
- 合法协议结果继续沿用 `Action.REQLLM` 与结果字符串回传；REQLLM 的含义是请求模型续答，**没有产生业务成功判定**。
- 不把原始 dict/list、非结构化 Python 对象自动包装成假 MCP 成功对象。

### 3.2 业务观察、分类草案及缺口

2026-11-12当前服务4.31的一次实际结果：MCP结果顶层`content/structuredContent/isError`，isError=false；`structuredContent`包含mode、generated、modelCalled、status、answer、sources、chunks、returned、topK、note、cacheHit、elapsedMs、model。实测status=ok、mode=chunks、generated=false、modelCalled=false、model为空字符串；sources为5项，content为6块。answer是组织后的来源原文，不是模型结论。服务自报returned=5、topK=5、cacheHit=false、elapsedMs=398；note明确“返回完整存储切片；不代表完整文档”，跨片或复杂图表须进一步读取/核对。来源/片段内含text、定位、修订、context、neighbors、uri等字段；资源URI与原文留受控服务器，本轮未继续resources/read。

因此，**不能单独用generated=false判定知识库失败或不完整**：当前工具声明不调用大模型，与该次chunks结果一致。也不能把status=ok和来源片段当最终模型回答完整。历史2026-11-10的incomplete→ok/true仍须按原始版本/模式复核，不能由这次检索成功覆盖。

以下名称仅为报告/本地设计标签，未新增上游字段或声称已全部接入产品状态机。

| 本地分类 | 拟处理/说明 | 已知与未知 |
| --- | --- | --- |
| 完整回答 | 检索结果符合适用模式和资料范围，并且模型依据结果完成输出后才计问答成功 | 已观察4.31原文/来源字段，但完整文档覆盖和模型终态未核实；不能凭HTTP200、来源或缓存命中判断 |
| 无命中 | 明确说明未取得知识依据，不伪造知识库答案 | 实际返回形状和状态值未知，合成 no_match 不算正式契约 |
| 不完整 | 按明确业务状态和适用版本判定，不记完整问答成功；后续成功不覆盖本轮失败 | 历史`status=incomplete`原始记录仍缺；当前4.31/chunks中的generated=false不单独代表不完整 |

| 协议错误 | 初始化、发现、结构或解析失败，固定安全错误 | 本地分支已回归，不代表真实服务出现过故障 |
| 拒绝/授权失效 | 依据权威响应和当前许可处理，不借用其他账号凭据 | 不把通用403解释为余额不足，也不从一次401推导生命周期 |

## 6. 超时、重试、取消与迟到（D-04）

| 阶段 | 当前本地默认/限制 | 边界 |
| --- | --- | --- |
| SSE连接 / 读取参数 | 5 / 300秒，可由现有配置覆盖 | 代码参数，不代表服务端承诺 |
| manager初次初始化 | 外层10秒 | 失败不注册，安全清理 |
| client关闭 | 正常宽限15秒，取消后再有界等2秒 | 小于manager外层20秒；不是远端停止证明 |
| manager单client清理 | 外层20秒；worker未结束时保留原attempt/引用，取消后二次等待仍pending抛TimeoutError，不误报成功 | manager关闭后禁止新调用/迟到注册；后续cleanup可继续回收同一worker |
| ConnectionHandler工具等待 | 代码默认30秒（本轮未改） | 超时仅结束本地等待，任务可能继续 |
| call_tool读取期限 | 可以透传显式期限；manager未额外设置该参数 | SDK有效默认和服务端限时不能混为一谈；本地chat等待上限不等于调用结束 |
| 模型续答 | 设计要求沿用并核对模型客户端的有限超时配置；本轮未加载真实模型配置、未修改或验证有效值 | 后续真实补验前记录实际值；无法确认有限上限时不执行对应真实请求，不凭MCP读取期限推导模型期限 |

### 本地策略

1. 已提交工具遇超时、断流、错误或结果未知时只返回安全失败，不自动重放；成功重连不是原请求可以再次执行的证明。本轮删除执行异常后的自动重试/重连/sleep。
2. 初始化可由后续明确调用在新attempt中重做；不自动无限重试，不新增连接池或幂等承诺。
3. 调用方取消保持传播。初始化/清理交错使用独立attempt状态，manager关闭时拒绝迟到注册。cleanup持锁有界等待，initializer在取得锁后拒绝仍closing的尝试，不承诺并发时无等待立即失败。清理期间取消或超时，若worker仍未结束则保留原attempt/task供后续回收，并如实报告未完成；不使用“已清理”掩盖pending任务。
4. 本地取消、超时、丢弃结果、发送取消请求、远端确认终态分别记录，不用断流代替远端已停止/不收费。
5. 超时片段回归已证明：合成工具仍运行，迟到成功未追加到原结果列表；未验证完整TTS/并发轮次围栏。

# 单次语音日程

在创建日程的音箱上说“明天下午三点提醒我开会”。音箱复述北京时间及事项后，说“确认”才会保存。也可说“查询日程”“修改第一项日程，改到后天上午九点”或“取消第一项日程”。查询按到期时间排序，每页最多五项，支持“查询日程第二页”。创建、修改和取消的确认限于同一语音会话，90 秒内有效。

管理后台在当前会话许可下从数据库确定设备及其归属代际。创建操作使用唯一 ID，修改和取消还检查已复述事项的版本。日程正文在数据库内加密。待办、已取消、已错过、播放结果未知和设备已确认播放分别记录。

## 待机到期通知

1. 支持提醒的固件在原有设备状态轮询 `GET /device-control/v1/state` 中携带 `X-Reminder-Protocol: 1`。许可有效且有到期日程时，响应的 `data.scheduled_reminder_id` 包含 32 位小写十六进制 ID。归属或许可版本未变化也能唤醒长轮询。旧客户端的响应保留原有字段。
2. 音箱空闲时，用现有许可开启独立产品语音会话，发送 `{"type":"reminder","state":"claim","id":"…"}`。服务端在同一事务内复核许可、归属代际、到期时间及状态。领取成功时将投递置为结果未知，后续轮询、重新领取和重启均不会重复发送。最晚允许领取的时间为原到期后十分钟。
3. 获得正文后，服务端发送 `reminder/start`，完整合成音频，依次发送 `tts/start`、Opus 二进制帧、`tts/stop` 及 `{"type":"reminder","state":"end","id":"…","frames":N}`。N 是成功发送的帧数。领取失败发送 `reminder/cancel`，中途中断可关闭连接。
4. 固件核对同一专属会话、ID、帧数和播放完成后，发送 `{"type":"reminder","state":"played","id":"…"}`。服务端只接受领取会话在正常结束标记之后的回执。失联或缺少回执均保留结果未知。

## 现场复核

同一台 P4 先查询日程，创建“一分钟后提醒我喝水”并确认，然后结束对话，等待待机播报。分别核对原声出现、答复“日程已保存”、管理端收到 `played` 和同一事项不会再次播报。再分别检查修改后旧时间无播报、取消后无播报、重启后待办仍在、同账号另一台设备查不到该事项，以及退出后无提醒内容。

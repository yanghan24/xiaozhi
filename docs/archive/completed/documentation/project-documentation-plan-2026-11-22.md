# 小智项目文档整理方案

> **归档｜交付或验证记录**。正文对应当时的版本、范围和结果。当前入口见[项目文档](../../../README.md)。

以当前服务端代码、P4X 固件和已核对的生产发布记录为依据。服务端根 README 面向接手项目的开发者，生产部署规范面向运维，固件文档面向固件开发者。用各自的入口描述当前实现和开发规则，按日期保存的实施与验收材料用于追溯。

## 第一阶段：服务端架构与术语

1. 重写根 README。先画管理 Web、Java API、Python 语音服务、音箱和外部服务之间的调用关系，再用模块表列出职责、源码和扩展位置。
2. 说明原版语音链路的会话鉴权、VAD、ASR、意图、智能体、大模型、工具、TTS、播放和打断。写明默认智能体的配置来源、下一轮切换和上下文边界。
3. 分别说明 AI 集市设备授权和模型接入。前者处理设备自动登记、用户扫码授权、归属、用户资料和解绑。后者处理目录客户端、兼容筛选、管理员选型、用户应用专用 Key 和提供者调用。核对当前支持的 ASR、TTS、LLM、视觉、意图、记忆及现有 VAD、RAG 的边界。
4. 写清设备管理、独立心跳、原版固件目录和按板型 OTA、按设备限时开启的诊断、MCP 管理与执行、系统设置和第三方服务。区分实际实现、生产发布和真机验收。
5. 将仍有用的术语归入对应模块，把容易混淆的概念留在 README 的术语小节。更新 AGENTS、领域文档约定和现有链接后移除独立词汇表。根 README 保留生产规范、当前生产状态和固件文档入口，删除过期的功能描述和旧阶段入口。
6. 写明整体架构、语音运行链路和智能体运行链路是稳定基线。功能优先在所属模块内扩展，独立职责可新增模块。需要改变基线或跨层契约时，先提方案并取得明确确认。集市、第三方、MCP 和系统密钥使用现有服务端管理机制。设备端仅按现有认证机制持有本台独立设备凭据和短期语音票据。手机浏览器负责集市扫码授权，固件的外部业务数据通过小智服务端获取。

## 第二阶段：生产部署规范

1. 在根 README 与 CONTRIBUTING 提供生产规范和当前状态入口。保留团队协作与实机验收原则，个人构建和环境步骤留在对应开发环境目录。
2. 以生产 Nginx 和 Compose 模板核对部署架构、转发职责、服务网络、业务端口和运行用户。文档记录业务拓扑以及服务器部署目录，生产登录、跳转、访问文件和凭据留在私有运维环境。
3. 明确 `/data/apps/xiaozhi` 和 `/data/apps/nginx`、`/data/packages`、`/data/backup`、`/data/bin` 的职责，以及部署视图、运维说明和更新日志的维护字段。普通文件操作由部署用户执行，需要管理权限的操作通过已授权的提权渠道完成。
4. 区分首次初始化、日常更新、启停和回退。明确开发构建与导出、传包与校验、备份、生产导入、启动顺序、配置和持久数据兼容检查及发布验证。
5. 详细记录 OTA 应用包和 USB 整包的区别、版本号和提交基线、精确板型、分区余量、SHA-256、发布前备份、下载校验、实机回执及回退边界。
6. 收敛 `docs/deployment/current.md` 为最近核验的现网状态、入口和发布证据。移除旧部署命令和过期入口，链接已存在的历史资料。保留当前版本、校验值、备份和验收状态供追溯。

## 第三阶段：固件项目与界面规范

1. 重写固件根 README，介绍官方 v2.6.0 基线、P4X 产品变体、系统分层、功能、开发规则与构建入口。上游归属和许可证保留，产品细节集中在板型文档。
2. 更新 P4X 产品文档。区分板级硬件、应用状态机、音频、协议、OTA、设备身份、Wi-Fi、设置、界面和本地应用。写明首次联网自动登记、账号扫码、配网双入口、声音与显示、屏保、关于设备、日历记事、番茄钟、SD 音乐和本地录音的代码入口及职责。保护原有系统设置、协议、持久化和音频优先级。
3. 将已确认的深蓝定稿归档在固件 `docs/ui/`。配套规范写明 800×480 横屏、全屏页面、公共导航和控件、开机及屏保、首页三列、周日历和提醒、五项设置、语音字幕和播放状态。设计稿作为文档素材，生产镜像只使用现有运行素材。图中的早期设置内容用当前界面说明补齐。
4. 写明每个功能模块的扩展位置与验证范围。音箱的外部业务访问经过现有小智服务端；集市和其他外部服务的密钥由服务端保管。

## 提交与验收

- 先提交本方案，再按三个阶段分别提交。服务端文档随服务端工作区提交，固件说明和设计素材随固件工作区提交。
- 检查 Markdown 文件和标题锚点、代码位置、板型标识、当前发布证据、目录职责、密钥边界和设计稿完整性。检查两个工作区的提交范围。
- 本次范围是文档与文档设计素材，验证采用源码与现有证据。服务器配置、发布目录、服务进程、固件代码和设备实机由各自任务另行处理。

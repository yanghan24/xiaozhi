# 音箱语音分段耗时

> **归档｜交付或验证记录**。正文对应当时的版本、范围和结果。当前入口见[项目文档](../../../README.md)。

设备详情沿用「上传诊断日志」。管理员按设备开启，30 分钟后自动到期，也可以提前关闭。音箱从鉴权心跳读取有效期，语音服务复用已有的设备会话校验取得同一有效期。

服务端用单调时钟记录收音、VAD、ASR、意图、记忆、模型首字、工具、首段合成和下发。音箱记录唤醒、进入收音、首包、首次提交给音频输出和队列播完。两端通过识别响应中的诊断轮次 ID 对齐，各自计算耗时。设备诊断页面展示音箱上报的事件，语音服务生成同轮的结构化耗时摘要。新增诊断只记录固定事件、耗时和轮次 ID。

上线顺序为管理 API、语音服务和管理页，再通过原版 OTA 发布 P4X 4.3 寸固件。开发环境验证开关、超时、日志脱敏、轮次配对和旧报告兼容。生产发布验证服务及公网固件下载，真机耗时单独验收。

## 查看一轮耗时

设备运行 2.6.7 并完成一次心跳后，在「设备管理 → 设备详情 → 设备诊断」打开「上传诊断日志」。完成一次问答后，等待下一次心跳，再用「刷新日志」查看音箱各阶段相对于该轮起点的时间。完整轮次 ID 可在耗时列悬停查看，语音服务日志以同一轮次 ID 输出 `voice_timing` 摘要。相邻阶段的耗时使用同一端的时间差计算。

服务端记录首个上行帧、检测到讲话、VAD 判停、ASR 请求和最终结果、意图处理、记忆读取、模型请求和首个有效文本。实际调用工具时记录工具等待，服务端 MCP 另记调用阶段。当前 Edge TTS 能区分开始合成、返回首个音频包、首段合成就绪和服务端首包下发。音箱端使用 WebSocket 收包和音频输出队列的实际事件计时。

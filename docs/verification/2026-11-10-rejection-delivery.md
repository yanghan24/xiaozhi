# 失效上报中断：共享禁用与可靠交付

2026-11-10，基线 abab265，Ubuntu issue13 隔离环境。本轮未调用付费集市、未撤销客户真实 Key、未部署生产。

## 旧行为

对模型、ASR 提交、ASR 查询分别注入 HTTP 401，同时让仅 key-rejected 返回 503 或超过两秒超时，原有 6 个场景都出现：发起连接结束，另一连接仍 allowed，并能通过正式 GuardedSocket 输出 WebSocket 消息。正常 Java 320 项回归不能发现这条故障路径。

## 修复边界

- 在可靠持久卷上保存加密失效回执与账号/授权顺序。所有本地输入、输出、资源调用及新连接先检查共享禁用。关闭源会话不删除待交付通知。
- 独立线程幂等重投，只接受 recorded=true 为确认；退避上限 30 秒，领取租约 30 秒，重启继续。付费模型/ASR 不重放。回执绑定用途、账号、授权代际和顺序，不再因故障超过五分钟而自动失效。
- 新增迁移 202611101200，记录每台设备明确 bind/resume 的许可授权顺序。重新登录不更新这个顺序：未交付失效期间重登也无法让其他旧许可绕过本地禁用；迟到回执在后台停用旧许可，同时保留后来明确恢复的许可及新授权。
- 容量满时，同一回执保持幂等；新失效无法接纳则持久标记故障并拒绝整个本地权威服务。故障标记在新进程仍有效，不能通过清空目录或重启绕过。目录与权威 URL 切换需迁移状态。

## 实际限制与恢复

当前按单语音实例部署；同机其他进程必须共享持久目录，跨主机副本尚无即时共享禁用保证。SQLite 不保存业务 Key 或录音，目录须保留、备份，禁止 tmpfs 或容器重建清空。已确认禁用记录保留至少 24 小时；未确认通知不自动丢弃。

底层存储若连故障标记也无法写入，只保证当前进程拒绝，不承诺重启保留未写入事件。运维必须暂停入口、恢复存储并核对/重投通知、处理未知范围旧许可后才能恢复，不能删库清标志直接放行。容量故障会暂停无关账号，是保守拒绝策略，容量扩展仍归 #19。

Java/Python 内部 scope、许可顺序和回执契约必须配套部署；回退保留迁移列和持久状态。双轴审查发现的重登绕过、容量重复上报和重启遗忘故障标记问题均已修复。未合并、未关闭 #11/#13。

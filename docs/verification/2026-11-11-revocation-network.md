# #11 撤销请求发送前网络故障验证

2026-11-11 15:33:15（香港时间），Ubuntu `jt@192.168.168.114`。沿用用户指定的同账号双机测试账号。API 实查 `xiaozhi-product-api:1468eeb`；使用已合并 PR #64 的专项工具，代码与 `503ba27` 相同。本轮没有修改工具或产品源码。

## 方法

有效令牌的 UserInfo、账号/应用及 Key 基线核对通过后，将一次撤销尝试置于 `unshare --net` 创建的临时独立网络命名空间。通过 `socket.if_nameindex()` 在发出请求前断言仅有 `lo`；没有接入外部网络、虚拟网卡对或转发。主机和现网容器网络未修改。

直接使用工具的固定 HTTPS 集市地址及真实测试会话，没有替换 HTTP 响应或构造 503。独立环境缺少对外连接，工具网络调用返回失败，无 HTTP 响应。一次调用耗时约 0.006 秒，属于立即连接/解析失败，不是等待到超时，也不证明远端返回过错误。隔离条件证明这次请求没有送达集市；仅靠工具的 `http=null` 本身不能作此判断。

之后在原主机网络下验证尝试记录会阻止再次执行。该核验使用拒绝发送的传输守卫，避免拦截失效时真的再次撤销。只读检查旧 Key、当前令牌、授权和设备状态，完成后移除临时明文状态。

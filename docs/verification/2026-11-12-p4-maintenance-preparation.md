## P4 设置入口

在当前产品 `860e045` 上增加「设置 → 恢复出厂」及二次确认。确认框说明将清除 Wi-Fi 和普通本机设置，保留设备身份、账号归属和停用状态；取消只关闭确认框。确认后在主任务停止音乐、录音、番茄钟及语音，调用既有 `ResetUserSettings` 跳过整个 `device_ctrl` 命名空间，成功后重启当前应用。失败时显示失败，停止重启。

仅在空闲、连接语音、聆听或回答状态下允许恢复；启动、激活、升级、音频测试、配网、未知和致命错误状态均拒绝。所有未解决的解绑都阻止恢复，包括界面显示失败或后台不支持但仍保留本机停音保护的情况。界面和主任务执行前各复核一次。未增加远端解绑、客户归属修改、凭据轮换或切回旧固件的操作。

独立增量、准确基点和重放方式见[补丁入口](../../integrations/firmware/README.md#p4-恢复出厂入口增量)。原 `00896ab → f03d98d` 身份恢复补丁保留，本次 `860e045 → a30f6a8` 增量保留当前本机解绑能力。

## 服务器恢复后的执行顺序

1. 重新核对[当前部署入口](../deployment/current.md)及 Ubuntu 实际 API/语音版本，由 B 验证真实扫码和完整回答。服务器仍不可达时记录受阻，保留当前 `860e045`。不以串口联网标志替代扫码或扬声器结果。
2. 在任何 OTA 或恢复出厂之前，重新采集当前应用/NVS、活动槽、稳定身份及 P4/C6，后台即时保存归属、`ownership_version`、本地许可、许可版本和停用状态。后端及协议检查在 Ubuntu 执行；真实标识、凭据和原始响应保持私有。
3. 确认设备可达的受控固件 URL 和升级发起通道后，提供上述校验值对应的产品 bin，检查下载内容及 `Content-Length`。既有用户专用工具 `self.upgrade_firmware` 可接收 URL，但服务器能否向 B 发起该工具调用仍需现场核实。当前未发布下载地址或修改公网发现接口。本候选应用版本仍为 `2.2.6`，自动版本比较不应作为升级触发依据；按实际受控通道显式选择候选。
4. 通过真实网络 OTA 安装，记录下载、写入下一槽和重启。候选应报告新 ELF，活动槽应从 `ota_0` 变为 `ota_1`；重新备份并离线比较身份和 `device_ctrl`，后台即时状态对照，验证扫码和完整语音。串口刷入不能计作 OTA 通过。
5. 在候选的设置页先验证取消无清理，再确认恢复出厂。重新配网后核对同一候选 ELF、稳定身份、当前凭据、P4/C6、可信地址、整个保护命名空间及后台归属/许可保持。后台已停用时仍保持停用并验证实际停播；正常许可下验证完整回答。设置清理失败不能记为成功。
6. 需要新的异常丢失/中断续作轮次时，先与服务器执行方确定注入边界和即时快照，保留当前代际的已完成 journal，并固定本轮产品/维护产物。恢复工具会创建新补发，当前不能为重跑旧 `f03d98d` 完成记录而刷回旧镜像、修改旧 journal 或还原旧 NVS。写入瞬间断电、整分区损坏及全片擦除仍需另行明确试验范围；本次没有执行这些注入。

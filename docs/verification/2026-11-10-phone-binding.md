# #13 手机确认后建立设备归属

日期：2026-11-10，Asia/Hong_Kong。本轮基于 PR #26 的 `a17d224`，复用 Ubuntu `/home/jt/issue13-integration`、`issue13-*` 独立测试容器及原有私有配置/测试数据库，不初始化现有服务数据库，不部署公网服务或刷机。

## 交付范围

真实设备控制 HTTP 发码 → 手机身份确认 → 手机点击确认 → 唯一归属持久化 → 设备 state 返回 bound。成功重试、请求消费和页面上下文与归属同事务。可信身份但业务凭据不可用也可绑定；当前仍不签发任何 voice/lease。完整行为及阶段性禁用策略见[开发说明](../development/customer-device-binding.md)。

## 红绿证据

| 场景 | 首次失败 | 修复 |
| --- | --- | --- |
| 手机最终确认 | confirm 没有协议成功结果，设备仍未绑定 | 新增事务接口及按钮 |
| 无业务 Key/Refresh | 3 个用例得到 IDENTITY_FAILED | 可信身份与业务授权分开保存，绑定保持 blocked |
| 非 JSON/form 的确认请求 | 管理异常封装返回 HTTP 200 | 精确兜底返回 400/INVALID_REQUEST |
| 重启后成功页 | 幂等结果已读回，中文页面被客户端错误解码 | 显式声明 UTF-8，保留原断言 |

## 回归覆盖

- 登录回调不自动绑定；手机显式确认成功，版本为 JSON 数字。
- 多账号并发及两个应用实例争抢：一个成功，其他不能覆盖；进程关闭/重建后同一归属和操作结果可读回。
- 错误身份、跨浏览器、CSRF/跨来源、凭据撤销、禁用、版本变化、请求替换、600 秒到期和网页闲置边界拒绝变更。
- 重复操作不增加版本；成功操作可在二维码过期后安全读回，网页身份仍须有效；旧成功不能撤销后续停用或跨新的归属代际使用。
- 无 Key、领取失败、无刷新能力、当前刷新结果未知时，绑定保持相应 blocked 状态，无 voice/lease；同账号其他授权不被删除。
- 真实 MySQL 操作结果保存故障使整个事务回滚，修复后同请求/同键可成功重试。

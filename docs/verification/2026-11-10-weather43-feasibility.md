数据路线为：

```text
本机回环 HTTP 请求
  → Ubuntu Open-Meteo 官方二进制，计算天气和 AQ
  → 专用 Docker 网桥上的 S3 字节转发器
  → Ubuntu SSH 回环转发 → Windows Clash
  → https://openmeteo.s3.amazonaws.com 的元数据、目录、真实 OM 文件 Range
```

全程不调用 `api.open-meteo.com` 或 `air-quality-api.open-meteo.com`，不使用天气 key 或付费 API。字节转发器不计算天气、不缓存结果、不生成模型值，保留真实源状态码、Range、ETag、Last-Modified；TLS 校验在访问 S3 时启用。转发网络只属于本次试验，不连接现有业务网络。

**路线限制：** 这证明 Ubuntu 能沿此获准代理链完成试验，不证明它脱离开发电脑后可长期独立访问 S3。当前数据源在海外，正式部署必须另有服务器可持续使用的出站网络；代理和网络成本仍然存在。

## 字段、单位和模型时间

成功查询明确指定 `models=gfs013` / `domains=cams_global`，每次环境请求同时调用本地 `/v1/forecast` 与 `/v1/air-quality`。6 个逐小时时间点均检查非空有限数值、单位、时间序列长度及当前小时覆盖，湿度范围为 0–100，PM 非负。代码不重试、不补零、不使用公共 API 回退。

[长沙真实响应样本](evidence/2026-11-10-weather43/real-response-sample.json)第一时间点为 **2026-11-10 15:00（Asia/Shanghai）**：

| `temperature_2m` | 14.8 | °C，室外模型估算 |
| `relative_humidity_2m` | 34 | % |
| `weather_code` | 2 | WMO 天气码 |

上述为带时间的模型样本，不是附近监测站观测或当前实时读数，不输出中国 AQI 等级。天气与 AQ 返回的网格坐标不同，不能强制当作同一观测点。

所用源元数据在前后两次读取中均一致：GFS 起报 `2026-11-10T00:00:00Z`，CAMS 起报 `2026-11-09T12:00:00Z`；有效时间来自各自响应，不能替换成取数时间。真实模型文件路径记录在 S3 relay 原始日志中。短时前后快照未出现新 run，因此**未验证跨发布周期更新**，更没有完成天气与 AQ 各自更新到应用缓存的持续验证。

## 负载结果

所有请求由同台 Ubuntu 产生，目标为回环自建端点。每个“设备请求”包含 **2 次 HTTP**，两个分量都验证成功才计入成功；这不是物理设备数或语音并发。表中 p95 从统一的计划到达时刻计到两类响应完成，包含压测器调度与排队。所有批次均为一次测量，未作置信区间或长期稳定性推断。

| 场景 | 请求数 | 成功 | 失败 | 超时 | p95 / 最大延迟（秒） |
| --- | ---: | ---: | ---: | ---: | ---: |
| 同城热缓存，350 同时到达 | 350 | 350 | 0 | 0 | 0.623 / 0.624 |
| 同城热缓存，1,000 同时到达，修正压测 FD 后 | 1,000 | 1,000 | 0 | 0 | 1.736 / 1.740 |
| 十城，已有一城预热、九城首次引入，350 同时到达 | 350 | 350 | 0 | 0 | 19.661 / 19.662 |
| 十城热缓存，350 同时到达 | 350 | 350 | 0 | 0 | 0.620 / 0.621 |
| 十城热缓存，1,000 同时到达 | 1,000 | 1,000 | 0 | 0 | 1.757 / 1.760 |

有效批次均严格使用 30 秒端点截止。十城包括长沙、北京、上海、广州、深圳、成都、武汉、西安、哈尔滨、乌鲁木齐的代表坐标。十城部分冷批次已有全局索引、字段头部和一城数据缓存，**不能等同于全新机器、全国不同网格的冷启动**。

1,000 台的 p95 超过方案中提出的 1 秒热缓存目标，虽全部在 30 秒内完成，也不能声称已达到 1,000 台产品 SLO。小智侧共享 JSON 结果缓存、限并发刷新、稳定网络及更多城市负载仍需测量。

### 保留的失败和故障恢复

| 场景 | 原始计数 / 时间 | 判断 |
| --- | --- | --- |
| 首次转发策略遗漏根目录 list | 1 次环境请求失败；两个分量均 HTTP 500 | 测试转发配置问题，放行必要的只读目录操作后保留原失败复验 |
| 修正 relay 后 ICON 查询 | 1 次环境请求失败，AQ 成功，天气仍命中之前的错误状态 | 保留失败；只重启本次天气容器后恢复 |
| ICON 完整诊断，120 秒截止 | 1/1 成功，响应约 108.950 秒 | 读取真实 native 网格，冷请求不能直接同步用于首页 |
| GFS 首次查询，30 秒截止 | 0 成功 / 0 失败 / 1 超时；AQ 约 10.36 秒成功 | GFS 同样需要后台预热，不将后续已缓存的成功冒充冷请求成功 |
| 1,000 台初次压测，FD 软上限 1024 | 507 成功 / 493 失败 / 0 超时；985 次 HTTP 在客户端报 `EMFILE` | 压测器瓶颈，不是模型容量结论；仅提高本次 shell 的 FD 到 8192，复测见上表，并给脚本增加预检 |
| 只停本次 S3 relay，保持热进程 | 1/1 成功，约 0.0066 秒 | 可继续读取已加载数据；原始引擎不提供产品所需的来源失败/过期封装 |
| 断源状态下仅重启天气容器 | 0 成功 / 0 失败 / 1 超时；10 秒截止 | 保留磁盘模型缓存仍不足以保证重启期间可用，需要独立持久化结果缓存 |
| 恢复 relay，再重启本次天气容器 | 1/1 成功，约 13.671 秒 | 恢复后重新取得真实字段；没有改业务服务、数据来源或数值 |

诊断的 120 秒截止及断源的 10 秒截止与负载批次不同，已分别记录，不把诊断成功当作 30 秒容量通过。故障注入仅停止试验 relay 或重启试验容器，没有改变全机防火墙、业务 DNS 或语音服务。

## 资源与共存边界

[完整计数与资源](evidence/2026-11-10-weather43/environment-and-results.json)保存各批次 `/proc` 原始计数、所有活动容器 Docker stats、镜像、资源限制和状态。主机指标包括同机压测器和其他业务，不能全部归因于天气服务。

| 观察 | 本轮值 | 限制 |
| --- | --- | --- |
| 天气 CPU 最大采样 | 183.27% | Docker 的 100%=一个逻辑 CPU；受 2 CPU 上限约束，短批次真实峰值可能漏采 |
| 天气 Docker 内存最大采样 | 116.5MiB | Linux Docker stats 会扣除部分缓存；不代表全部 cgroup/page cache 内存，更不能据此把官方 8GB 基线改成 128MB |
| 主机 MemAvailable 最小采样 | 13,001,800 KiB，约 12.4GiB | 无主动语音压力，不证明同时大规模语音的余量 |
| 模型缓存磁盘 | 约 8GiB 已实际分配 | 固定预算，不是“只读了多少网络字节就只占多少磁盘” |
| 结束时可用磁盘 | 约 430.9GiB | 包含镜像、归档和本次缓存的占用 |
| S3 relay 累计读取响应体 | 106,652,921 字节，约 101.7MiB | 包括两种天气候选、目录和元数据；未含镜像下载、TLS/SSH 开销或重传，不是生产带宽报价 |

试验期间产品 API、产品 voice、既有管理服务和数据库继续运行，保留的 JetLinks 仍停止。**未执行主动语音工作负载**，没有以空闲连接或容器存活替代语音共存验收。要回答正式共机与扩容问题，还需相同版本的语音基线在环境负载前、中、后重复比较，并观察更新与缓存淘汰。

## 继续实施的方案

推荐先采用固定 GFS 模型 + CAMS 全球作为验证基线，让小智环境服务维护**按城市共享且跨重启保留的结果缓存**。模型文件缓存与面向设备的结果缓存分开：前者由 Open-Meteo 管理，后者保存字段、模型起报/发布时间、有效时间、来源和过期状态。

- 同城请求合并刷新，设备错峰取缓存，模型查询使用有界并发；冷城市先显示正在获取或明确无数据，后台完成后更新。
- 天气、温湿度和 AQ 分别判断更新与过期；来源失败不推进模型时间、不补零。断源重启先读持久结果，避免等待模型目录重新初始化。
- 固定镜像与模型别名，升级时重新核对实际存储域、字段和冷启动；本轮已说明 API 别名可能触发不同数据布局。
- 先落实服务器独立、获准的出站网络，再运行 30 分钟稳态、完整冷缓存、35/350 个不同城市网格、TTL 失效和至少两次 AQ 新批次发布验证。
- 离线 GeoNames / DB-IP 候选的许可与更新资料见方案，中文消歧、IPv4/IPv6 大陆样本和精度仍未实测；正式设备认证与 P4 UI/语音城市设置分别与后续任务衔接。

当前没有必须购置新服务器的证据。建议先按本轮 2 CPU/8GiB 上限继续验证，测量长期 page cache、城市分散与主动语音竞争后决定是否拆分独立天气节点。现阶段不作零成本、永久可用、全国准确或 1,000 台已正式验收的承诺。

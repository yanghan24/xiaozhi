# 2026-11-12 A2 无命中/非法参数与 A6 模型配置名实测

在 `6bf7620` 基线、复用客户端与真实 SDK 下，对 A2 与 A6 可自主完成的部分做实测。不调模型、不调 TTS，每个用例只提交一次，无重试。

## 1. A2：真实返回形状

探测脚本 `probe-a2-behaviour.py`（SHA-256 `05c1be48c33fbc7dab778de31022e355c262c0797aa960e3b460edeebfae1639`）与 `probe-a2-errors.py`（SHA-256 `e60e1bb67c74e4f5a3bee8301640bd4849aa27b3581fbee8f4094214151c8db2`），运行于固定镜像容器，host 网络只出站，只读根文件系统、非 root，仅只读挂载受控 MCP 配置。

| 用例 | 输入长度 | 结果 |
| --- | --- | --- |
| 无相关知识问题（“今天火星基地的食堂几点开饭”） | 13 字 | **正常返回** `CallToolResult`，`is_error=false` |
| 超长问题 | 301 字 | 协议错误 `MCPError`，`code=-32602` |
| 空问题 | 0 字 | 协议错误 `MCPError`，`code=-32602` |

非法参数错误消息为“只接受问题字符串，长度为1至300字”，与 `tools/list` 声明的 `minLength=1` / `maxLength=300` 一致。客户端侧按协议直接失败，不进入业务结果。

### 关键发现：无命中没有独立信号

无相关问题时，返回结构与正常检索**完全相同**：

- `is_error=false`，`status=ok`，`mode=chunks`，`generated=false`，`modelCalled=false`，`model` 为空
- `returned=5`、`topK=5`、`cacheHit=false`、`elapsedMs=256`
- `sources_count=5`、`chunks_count=5`、`answer_chars=125`、`content_blocks=6`
- 内容块类型为 `text` + 3 个 `resource_link`，`note` 仍为“返回完整存储切片；不代表完整文档…”

结论：**该服务没有“无命中”状态字段或降级标记**。它按 topK 返回切片，命中与否只能由调用方根据内容相关性自行判断。因此：

1. 不能把 `status=ok` 当作“知识库有答案”的证据；
2. 不能把 `returned=5` 当作“有相关内容”的证据；
3. A2 要求区分“无命中”，在当前协议下**没有服务端信号可依赖**，只能由上层语义判断。

这一条同时说明：`generated=false` 是当前 chunks 模式的常态，不是异常；把它当“不完整”会误判，把它当“完整”也会误判。

### A2 仍未覆盖

- 历史 `incomplete/generated=false` 的真实样例：当前服务为 chunks 检索模式，与 2026-11-10 摘要描述的模式可能不同，未取得可核验原件。
- 工具错误（`is_error=true`）与协议层其他错误（如限流、服务故障）的真实样例未触发。
- 因无命中无状态信号，“不完整结果不得标为完整问答成功”在服务端只能靠内容判断，无法用字段断言。

## 2. A6：模型配置名称

只读检查运行中语音容器内的 `/app/data/.config.yaml`（0600 root）：

- 顶层键：`manager-api`、`product-voice`、`prompt`、`prompt_template`、`server`
- **没有 `LLM` 段，也没有 `selected_module`**（`selected_module=None`）

结合源码：

- `websocket_server.py` 在产品模式下强制 `config['LLM'] = {'MarketModel': {'type': 'market', 'model_name': 'qwen3.8-flash'}}`，模型名由代码固定，不读本地 `LLM` 配置。
- `product_voice.py:114` 的 `model_access()` 强校验 `result.get('model') != 'qwen3.8-flash'` 即拒绝。

结论：**模型配置名称 = `qwen3.8-flash`，由代码固定并在每次 model-access 时校验**，不来自私有配置文件。这意味着 A6 的“模型配置名称”一项可以给出确定答案，但它的来源是代码而非可切换的配置项。

### A6 仍未覆盖

- 工具独立版本仍未暴露，只有服务版本 `4.31`。
- 服务/工具升级规则未知。
- 实际生效的模型凭据由私网 `model-access` 按设备许可下发，本任务未获取。

## 4. 对结论的影响

- **A2 仍不可签收**，但缺口性质变了：不再是“没测”，而是“服务端没有无命中信号”。这是协议事实，需要写进契约并交接 #14。
- **A6 的模型配置名已确定**（`qwen3.8-flash`，代码固定+运行期校验），剩余缺口是工具版本与升级规则。
- 该发现应反馈给 MCP 维护方：若需区分无命中，需要服务端提供状态字段或相关度阈值，客户端无法自行可靠判断。

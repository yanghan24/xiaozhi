# 唤醒与首段语音延迟优化

2026-11-13，Ubuntu `jt@192.168.168.114`。针对[现场诊断](2026-11-13-voice-latency.md)中唤醒约 4 秒、数数请求模型开始至首帧 13.009 秒的等待，完成固定问候缓存、首段分句和 Edge 增量解码。下面的真实网络合成对照与隔离协议测试分别记录，不能当作优化后物理扬声器延迟。

## 改动

- 授权产品会话唤醒播放固定“我在，请说”，复用正常发送、轮次与授权检查，不再为问候调用模型或在线合成。配套首次 `listen/start` 仍保留问候；后续监听、打断和授权撤销仍停止旧轮。
- 首段文本在最早且不切开引号的标点处分段，后续合并方式保持原行为。模型工具选择仍完成后再交付文本，知识库查询前的草稿不提前播报。
- 产品模式下的 Edge MP3 → Opus 改为分块解码与编码，收到可播放帧即排队。PCM 等其他路径沿用原处理。每次在线合成前重新检查权威许可及轮次；仅在尚未排出任何语音帧时最多尝试两次，避免已播放的回答重播。

固定问候资源位于 `main/xiaozhi-server/config/assets/product_wakeup.wav`，由 Ubuntu 上的 Edge Xiaoxiao（rate `+0%`、volume `+50%`、pitch `+0Hz`）生成，再解码为 24 kHz 单声道 PCM；只含固定产品用语。SHA-256：`d62e0993fc0ab412df7eccd5c2869f12a22d7cf30c8403965fb65d687a54403a`。按协商采样率／Opus 或 PCM 缓存编码结果。资源不可用时结束本次播报，下一次普通问题仍可处理。

## 真实 Edge 对照

同一 Ubuntu 网络、相同正式音色参数，16 字与 97 字两段公开固定文本，新旧版本交错测试，各组 5 次，共 20 次。全部成功、无重试；直接回调的首个 Opus 包经实际解码成功后才记为首音频时间。

| 文本 | 原版首个可解码 Opus 中位数 | 增量版中位数 | 提前 |
| --- | ---: | ---: | ---: |
| 16 字 | 1.776 秒 | 1.265 秒 | 0.512 秒 |
| 97 字 | 4.550 秒 | 1.453 秒 | 3.098 秒 |

短句两版均为 62 帧／178560 字节解码 PCM，长句均为 342 帧／984960 字节；相同公开输入的输出帧数和字节数一致。测试并不保证每次网络请求都同样快；增量版长句最慢完整接收仍为 6.255 秒。每组只有 5 个样本，记录中的 p95 等于组内最大值，不能估计长期尾延迟。

对照基线镜像 `f931a8ea…`，增量候选 `bc571ea4…` 仅替换 Edge 模块。该对照早于最后的授权检查修复，用于验证增量解码收益；完整产品权限、模型、WebSocket 传输及物理音箱不在其计时范围。[脱敏原始样本与汇总](evidence/2026-11-13-voice-optimization/edge-opus-comparison.json)包含精确 digest、脚本 hash、交错顺序和计时。

## 失败回归与修复

- 原问候路径遇到阻塞模型时 3 秒内无音频；缓存路径在隔离 WebSocket 夹具中约 65 ms 发出首帧，不调用模型或在线合成。另测 16 kHz Opus 和 24 kHz PCM、打断、授权撤销、资源损坏后下次问题恢复。
- 原首段为“你好，我是语音助手”；修改后首次合成为“你好”。三个真实 WebSocket 入口场景检查最早标点、引号保护和无标点尾段，完整文本无丢失或重复。
- 阻止最后一段 MP3 到达时，原版无法输出；增量版提前输出可解码 Opus，放行剩余 MP3 后全部 Opus 包与完整文件解码基线逐包一致。另测首帧后失败不重试、网络停滞期间取消及下一轮恢复、首帧前超时最多两次。
- 审查发现增量路径绕过原 `text_to_speak` 包装器。以实际 `VoiceGate` 和受控外部权限接口新增两项回归：权限已撤销但周期检查未观察到、权限检查期间取消。修复前两项失败；每次外发前补权威检查和轮次复查后，6 项 Edge 回归全部通过。
- 取消长音频时，审查复现解码管道尚未关闭导致 `BrokenPipeError`／事件循环关闭警告；未复现线程卡死或文件描述符增长。新增回归先失败，再补有限时的输入管道关闭和输出排空；最终 7 项 Edge 回归全部通过，取消后没有异步清理异常。

全部后端测试在 Ubuntu 隔离容器执行；固定测试文本、合成音频及外部传输夹具不使用真实设备身份或客户内容。测试依赖仅安装到隔离测试目录，未加入产品镜像。

## 审查

按固定基线 `7ca583ad48b4f033a0e3840c75129eb8e73b94c4` 分别进行 Standards 与 Spec 独立审查。Standards 要求补齐诊断设备环境，已用同会话 MCP 自报板型／固件并注明取证边界。Spec 发现在线合成授权与取消管道清理问题，分别在 `bcb92df`、`c0d6708` 修复，针对修复静态复核通过；未证明原取消问题导致线程卡死或描述符泄漏。

后续环境改进建议：将这些“首帧前仍阻塞后续网络”“权限撤销后零外发”“取消后无未处理异步异常”的回归接入固定 Ubuntu 检查入口，防止以后替换 TTS 实现时漏掉连接层的保护。这是本次复盘建议，不扩大本次产品功能。

# PR #26 授权失效竞态修复验证

2026-11-10，基线 1663a16，Ubuntu issue13 隔离环境，真实 MySQL/Redis/HTTP；外部集市由 ControlledMarket/HTTP 服务替代，没有真实撤销客户 Key 或重复付费调用。

## 问题与修复

1. 刷新失败终态原先不参与 identity barrier，登录事务可能读到旧 REFRESHING 再覆盖为 ACTIVE。终态提交、崩溃遗留收口和依赖设备停用现在共用登录替换屏障并原子提交；回调使用 READ COMMITTED，旧代际结果由 CAS 排除。刷新外部网络调用仍在锁外。
2. 模型/ASR 对携带业务 Key 请求的 HTTP 401 现在上报权威服务。使用 model-access 签发的 5 分钟加密回执绑定原账号及授权代际，支持断线删会话后迟到的拒绝；旧代际不能伤及新授权。匹配时停用该授权依赖的启用设备，保留已退出设备状态和归属。普通资源失败、无业务 Key 的结果 URL 401 不作授权撤销。

## 执行证据

- 新回归先红：两个刷新模式在持有替换屏障期间仍提交 REAUTH_REQUIRED / REFRESH_UNCERTAIN；旧 API 没有失效传播凭据。定向测试原为 12 项中 2 failures、1 error。
- 修复后的完整 Java：320 tests、0 failures、0 errors、0 skipped，集成测试守卫通过。覆盖刷新明确/未知失败锁屏障、共享设备停用、显式只恢复目标、旧代际回执、会话删除后拒绝上报，以及畸形/过期回执拒绝。此前已有旧刷新响应与新登录隔离用例继续通过。
- `scripts/check-product-key-rejection.py`：真实 Java 权威接口 + Python 模型/ASR 适配器通过；模型 401、ASR 提交 401、ASR 查询 401 均使其他连接校验拒绝，临时音频清除；未携 Key 的结果下载 401 保留许可。

- 原有 scripts/check-product-voice.py 和 scripts/check-product-asr.py 回归均通过，覆盖余额不足保留许可、旧鉴权拒绝、多连接退出、延迟 TTS 拦截、ASR 失败/超时、断线和连续音频打断。

## 范围

本轮不声称独立撤销真实集市 Key 的实测；验证的是收到明确 401 后的处理与传播。尚未调用、也未收到通知时无法提前得知远端撤销。回执及内部服务密钥都只留在后端，Java/Python 必须配套更新。本次无数据库迁移、未合并或部署生产，#11/#13 保持开放。

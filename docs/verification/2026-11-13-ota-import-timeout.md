# 固件导入传输时限补充验证

2026-11-13，在线 OTA #95。#97 浏览器两次真实导入失败后，使用与隔离 API 相同的 Docker 网络、原始 `GithubReleaseSource` 下载逻辑及正常 TLS 复现，诊断只输出阶段、主机、字节数、错误类型与耗时，不输出重定向签名 URL。

## 发现

Release/manifest 请求和固件响应头正常。一次持续传输在 60.446 秒仅收到 2,598,464 / 4,003,072 字节，随后总时限触发；原错误被归为 GITHUB_UNAVAILABLE。另一些运行在 30 秒无新数据后触发读取超时。正常 DNS 的一次完整传输在 42.902 秒完成；替换目标 DNS 地址也出现停顿，因此没有据此修改生产 DNS，不能保证增大总时限能解决空闲停顿。

管理 Nginx 源码与当时运行配置的普通代理等待均为 30 秒，即使 42.902 秒的成功下载也可能被入口提前截断。

## 调整与验证

- 镜像下载总预算改为 180 秒，元数据为 30 秒；连接 15 秒、无新数据读取 30 秒的限制保留，最多 5 次允许域名重定向、大小上限、HTTPS 与摘要校验保留。总预算到期准确归为 GITHUB_TIMEOUT。
- 只为 `/xiaozhi/admin/product-ota/firmware` 精确管理路径增加 300 秒代理等待；普通路径仍为 30 秒，认证仍由原管理过滤链执行。
- Ubuntu 独立离线容器编译通过，日志 `/home/jt/ota95-import-compile.log`。未启动后端服务或重复运行已通过的完整回归；后续集成版本需包含此调整的回归记录。
- Ubuntu 独立内部 Docker 网络使用合成延迟 HTTP 上游与实际管理 Nginx 配置，`nginx -t` 通过；POST 精确路径等待 31.04 秒后收到预期 200。该项仅验证路由等待，不验证登录或真实 GitHub 导入。临时容器与网络已清理。

诊断记录留在任务私有资料 `D:/AI/ota-management-notes/github-import-network.md`，未复制任何秘密或原始运行日志。现网服务、DNS 与代理配置未修改。上述修改改善有进度的慢下载并保留失败边界，不将外部网络恢复或真实安装记为已验收。

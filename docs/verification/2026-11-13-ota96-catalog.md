## TDD 与修正记录

先在已确认管理 HTTP 边界观察不存在目录的 404，再实现认证目录；随后导入读回测试因缺少 Release 接口失败，再实现固定资产。未知 URL 字段测试发现默认反序列化会忽略额外字段，改为严格字段/重复字段/整数/请求大小校验后通过。私有管理 HTTP 测试发现复用交付过滤器会强制 HTTPS；新目录使用相同 Bearer 认证但支持现有 SSH 隧道私有 HTTP，原交付接口 HTTPS 约束不变。

页面先观察组件不存在失败，再通过真实模板挂载验证 Release 选择、导入、刷新及固定构建选择。GitHub 错误时旧目录不可用的测试失败后，改为分别读取外部 Release 和持久目录；错误仍显示，已校验固件可继续查看。

最初真实下载在 10 秒读取超时下失败且未写目录。连接/读取上限调整为 15/30 秒，下载数据循环检查 60 秒截止时间后成功；另以隔离容器 Java 网络探测确认 API、资产重定向及完整 4,003,072 字节下载。没有使用本地缓存替代最终真实 probe。前端依赖从既有工作区复制到本工作区，没有修改原工作区。

## 保留边界与恢复

仅支持明确 P4 板型和已知 16 MiB 布局；缺少 manifest、GitHub digest 或兼容元数据的旧 Release 会被拒绝。分区表 SHA 属于发布元数据，实际目标设备仍须发布前独立核对。新目录未改变客户归属、许可、设备凭据或运行状态。

迁移只新增 `dc_ota_firmware`。停止提供目录入口可暂停新导入；保留新增表和固定字节以支持后续发布引用。没有设置匿名固件下载路由，也没有开放任何公网管理入口。
